# 0-2 挫折しない学び方の設計

> 🎯 **このレッスンのゴール**
> - 自分の生活に合った、現実的な学習計画を1枚作る
> - 学習が止まる仕組みと、止まらない仕組みの違いを理解する

所要 30分 / 難度 🟢

---

## 挫折は「意志」ではなく「設計」の問題

学習が続かなかった人の多くは、こう振り返ります。「自分は意志が弱い」。

しかし実際に止まる原因を分解すると、意志とは別のところにあります。

| 止まる原因 | 実態 |
| --- | --- |
| 「今日はやる気が出ない」 | **開始のハードルが高い**（PCを開く → エディタを開く → どこからだっけ？） |
| 「時間が取れなかった」 | **学習時間が固定されていない**（空いた時間にやろう＝やらない） |
| 「難しくて止まった」 | **1回の学習単位が大きすぎる**（1日で1章、は大きい） |
| 「何のためにやってるか分からなくなった」 | **ゴールが遠すぎる**（3ヶ月後に転職、では毎日の燃料にならない） |

対策はすべて設計でできます。

## 設計1：時間を「先に」決める

「空いた時間にやる」は、ほぼ確実に失敗します。カレンダーに**予定として**入れてください。

おすすめは以下のどれかです。

- **朝型**：起床後すぐ 60分（最も中断されにくい）
- **通勤型**：行き帰りの電車で読む 40分 + 帰宅後に手を動かす 40分
- **夜型**：夕食後 90分（ただし就寝直前は定着が悪いので避ける）

> 💡 **1日30分でも意味があります**
> 週1回3時間より、毎日30分のほうが定着します。プログラミングは「思い出すコスト」が大きいので、間隔を空けないことが最優先です。

## 設計2：学習単位を小さくする

**1レッスン＝1セッション**を基本にしてください。この教材のレッスンは 60〜150分に収めてあります。

大きい総合演習（🔴 300分クラス）は、必ず分割します。

```
【総合演習】ToDoアプリ（300分）
 ├─ Day1: HTML構造とCSSだけ作る（90分）
 ├─ Day2: 追加機能を実装（90分）
 ├─ Day3: 削除・完了機能を実装（60分）
 └─ Day4: localStorage で保存（60分）
```

**「今日はここまで」を先に決める**と、キリの悪いところで終わって翌日再開できない事態を防げます。

## 設計3：中断からの復帰コストを下げる

明日の自分は、今日の自分が何をしていたか覚えていません。学習を終えるとき、**必ず次の3行をメモ**してください。

```markdown
## 2026-04-10
- やったこと: レッスン2-6 DOM操作。querySelectorまで
- 次にやること: 2-6の演習3から
- 詰まっていること: addEventListenerの第2引数がなぜ関数名だけなのか未消化 → 明日AIに聞く
```

このメモがあるだけで、翌日の立ち上がりが 10分 → 30秒 になります。

> ✍️ **手を動かす**
> 学習用のフォルダに `learning-log.md` を作ってください。あとで作る、は忘れます。今作ります。

## 設計4：ゴールを近くに置く

「3ヶ月後に転職」は遠すぎます。**2週間で1つ、人に見せられるもの**を目標にしてください。

| 時期 | 見せられるもの |
| --- | --- |
| 2週間後 | 自己紹介ページ（HTML/CSS） |
| 1ヶ月後 | カフェのLP（レスポンシブ対応） |
| 2ヶ月後 | ToDoアプリ |
| 3ヶ月後 | 掲示板アプリ（DB連携） |
| 4〜5ヶ月後 | フリマアプリ（Laravel・認証つき） |

作ったら、スクリーンショットを撮って残してください。**振り返ったときの成長の証拠**が、続ける燃料になります。

## 🤖 AIに聞いてみよう

計画を立てたら、AIに現実性をチェックしてもらいましょう。

```text
私はプログラミング未経験で、Web開発（HTML/CSS/JavaScript/PHP/Laravel）を
学ぼうとしています。総学習時間の目安は180時間です。

私の生活状況は以下の通りです。
- 平日は仕事で、帰宅は20時頃
- 平日に確保できそうな時間: 1日1時間
- 休日に確保できそうな時間: 土日それぞれ3時間

この条件で、無理なく続けられる週間スケジュールを提案してください。
また、この計画が崩れやすいポイントと、崩れたときのリカバリー案も教えてください。
```

> 💡 AIに相談する価値は「正解をもらうこと」ではなく、**自分の状況を言語化させられること**にもあります。上のプロンプトを書くために自分の生活時間を数えた時点で、半分は成果です。

> 🆘 **ここで詰まったら**（計画が崩れて、数日空いてしまった）
> - **考え方**：計画は**崩れる前提**です。空いた日を取り戻そうとせず、「今日の1コマ」から再開すればOK。続けている人は、皆これをやっています
> - **再開が重いとき、AIにこう聞く**：
>   「プログラミング学習を数日休んでしまい、再開が億劫です。前回は○○まで進んでいました。今日30分で無理なくできる、再開のための小さな一歩を提案してください」
> - **止まる原因が「難しすぎる」なら**、そのレッスンの難度（🟢🟡🔴）を確認し、🔴は時間を多めに見積もる／一度飛ばして戻る、と割り切ってください。

## ⚠️ つまずきポイント

**「計画通りに進まない」ことに落ち込んで、そのままフェードアウトする**

これが最頻出の脱落パターンです。計画は**必ず崩れます**。プロの開発現場ですら見積もりは外れます。

対策は、計画に**バッファを入れておく**ことです。

- 週の学習日を「5日」にする（7日にしない）
- 余った2日は、遅れの吸収と復習に使う
- 3日連続で休んでも、4日目に再開すれば計画は生きている

**連続記録を切らさないことより、通算時間を積むことが目的**です。
