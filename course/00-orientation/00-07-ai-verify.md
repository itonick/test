# 0-7 AIの答えを疑う技術 — 検証編

> 🎯 **このレッスンのゴール**
> - AIの回答が信用できるかを、初学者でも判定できるようになる
> - 5段階の検証手順を身につける

所要 60分 / 難度 🟡

## この技術が、あなたの市場価値になる

いま、「AIにコードを書かせられる人」は珍しくありません。誰でもできます。

希少なのは、**「AIが出したコードの正しさを判断できる人」**です。

現場で起きていること：

- AIが出したコードをそのまま入れて、SQLインジェクションの穴が空いた
- AIが提案したライブラリが、実は3年前に開発終了していた
- AIが「動く」と言ったコードが、特定の条件でだけ壊れた

これらを**リリース前に止められる人**が、いま最も評価されています。このレッスンで、その第一歩を踏みます。

## AIが間違える5つのパターン

### パターン1：存在しないものを作る（ハルシネーション）

```php
// AIが自信満々に提示してきたコード
$reversed = str_reverse($text);  // ❌ こんな関数はPHPに存在しない
```

**なぜ起きるか**：AIは「それっぽい次の単語」を予測しています。`str_replace` `str_split` `strrev` …と似た名前が学習データにあるため、`str_reverse` という**あってもおかしくない名前**を生成してしまいます。

**見抜き方**：関数名を公式ドキュメントで検索する（後述）。

### パターン2：情報が古い

AIには**学習データの締め切り**があります。それ以降の情報は知りません。

```php
// AIが出してくることがある古い書き方
mysql_query("SELECT * FROM users");  // ❌ PHP 7.0 で削除済み
```

**見抜き方**：「この書き方は現在も推奨されていますか？ 非推奨になっていませんか？」と追加で聞く。ただしAI自身も気づいていないことがあるので、**最終判断は公式ドキュメント**です。

### パターン3：バージョンがずれている

Laravel、PHP、JavaScript は頻繁に更新されます。AIは、質問者が使っているバージョンを知りません。

**対策**：質問時に必ずバージョンを書く。

```text
Laravel 11 / PHP 8.2 を使っています。
```

### パターン4：質問を誤解したまま、完璧な答えを返す

あなたが聞きたかったことと、AIが答えたことがズレているのに、答えの完成度が高いので気づけない、というパターンです。

**見抜き方**：AIの回答の冒頭に「あなたの質問はこう理解しました」と要約させる。

```text
回答の前に、私の質問をあなたがどう理解したかを1〜2文で要約してください。
```

### パターン5：動くけれど、まずいコード

**これが最も危険です。** 動いてしまうので、初学者には問題が見えません。

```php
// 動く。しかし危険
$sql = "SELECT * FROM users WHERE name = '$name'";  // ❌ SQLインジェクション
```

```php
// 動く。しかし危険
echo $_POST['comment'];  // ❌ XSS
```

**対策**：AIに書かせたコードには、必ず**セキュリティレビューを別途かける**（後述のテンプレート参照）。

## 検証の5ステップ

AIの回答を受け取ったら、この順に確認します。**慣れれば1〜2分です。**

```
STEP 1  自分の言葉で説明できるか？
   ↓ できない
   → 理解できるまで聞き直す。理解できないコードは使わない

STEP 2  出てくる関数・メソッドは実在するか？
   ↓ 公式ドキュメントで検索

STEP 3  実際に動かして、期待通りか？
   ↓ 正常系だけでなく、異常系も試す

STEP 4  セキュリティ上の問題はないか？
   ↓ 別のプロンプトでレビューさせる

STEP 5  もっと簡単な方法はないか？
   → AIは複雑な解を出しがち。「もっと簡単に」と聞き返す
```

---

### STEP 1: 自分の言葉で説明できるか

**最重要のステップです。**

AIが出したコードを見て、「この行は何をしている？」に答えられなければ、**そのコードは使ってはいけません**。

答えられないときは、こう聞きます。

```text
いただいたコードの、以下の行の意味がわかりません。

（該当行を貼る）

この行がないとどうなりますか？
また、この書き方以外の方法はありますか？あるなら、なぜこの書き方を選んだのですか？
```

> 💡 **「これがないとどうなる？」** は、理解を確認する最強の質問です。役割がわかっていないと答えられません。

---

### STEP 2: 実在するか公式ドキュメントで確認する

**公式ドキュメントのURL（ブックマーク推奨）**

| 技術 | URL |
| --- | --- |
| HTML / CSS / JavaScript | https://developer.mozilla.org/ja/ （MDN） |
| PHP | https://www.php.net/manual/ja/ |
| Laravel | https://laravel.com/docs |
| MySQL | https://dev.mysql.com/doc/refman/8.0/ja/ |

**確認の仕方（PHPの例）**

1. `https://www.php.net/manual/ja/function.strrev.php` のように、`function.関数名.php` でアクセスできます
2. または php.net の検索窓に関数名を入れる
3. **ページが存在しなければ、その関数は存在しません**

> ✍️ **手を動かす**
> `https://www.php.net/manual/ja/function.str-reverse.php` を開いてみてください。
> 「該当ページが見つかりません」と出ます。これが、AIの嘘を見抜いた瞬間です。
> 次に `https://www.php.net/manual/ja/function.strrev.php` を開いてください。存在します。これが正解です。

> 🆘 **ここで詰まったら**（公式ドキュメントが英語・専門的で読めない）
> - **考え方**：読めないから確認を飛ばす、が一番危険。**AIを「翻訳・要約係」として使い、ただし原典リンクは必ず自分で開く**のが安全な折衷案です
> - **AIにこう聞く**：
>   「次の公式ドキュメントのページの内容を、初心者向けに日本語で要約してください。あわせて、①この関数（機能）は現在も推奨されているか ②非推奨・廃止予定でないか を、ページの記述にもとづいて教えてください。（URLまたは本文を貼る）」
> - 要約は便利ですが、**AIが原典を誤読することもあります**。最後は自分でページを開き、関数名・引数・バージョン表記を目で確かめてください。

---

### STEP 3: 動かして確かめる — 異常系を忘れない

初学者がやりがちなのは、**うまくいくケースだけ試して「動いた」と判断する**ことです。

以下も必ず試してください。

| 試すこと | 例 |
| --- | --- |
| 空の入力 | フォームを何も入れずに送信する |
| 想定外の型 | 数値のはずの欄に文字を入れる |
| 極端に長い入力 | 1000文字貼り付ける |
| 日本語・絵文字 | 「あいうえお🎉」を入れる |
| 特殊文字 | `'` `"` `<script>` `&` を入れる |
| 0 と マイナス | 数量に `0` や `-1` を入れる |

> 💡 これは**テスト設計**という、れっきとしたエンジニアリングスキルです。第5部（5-14）で本格的に学びます。

---

### STEP 4: セキュリティレビューをかける

AIに書かせたコードは、**別プロンプトで**必ずセキュリティを見させてください。同じ会話の続きではなく、**新しい会話で**聞くのがコツです（自分が書いたコードを庇う傾向を避けるため）。

```text
以下のコードを、セキュリティの観点からレビューしてください。
このコードはWebアプリケーションで一般ユーザーからの入力を扱います。

（コードを貼る）

次の観点で、問題があれば具体的に指摘してください。
- SQLインジェクション
- XSS（クロスサイトスクリプティング）
- CSRF
- ファイルアップロードの脆弱性
- 認証・認可の不備
- 機密情報のハードコーディング

問題がない場合も「問題なし」と明言してください。
それぞれについて、なぜ危険なのか、攻撃されるとどうなるかも説明してください。
```

---

### STEP 5: もっと簡単にできないか聞く

AIは、聞かれた通りに答えます。回りくどい方法でも、それが答えられるなら答えます。

```text
このコードは、もっと簡潔に・読みやすく書けますか？
初学者が読んでも理解できることを優先して、書き直し方を教えてください。
また、あえて簡潔にしないほうがよい理由があれば、それも教えてください。
```

## AIに任せてよい領域 / いけない領域

```
┌──────────────────────────────────────────────┐
│ ✅ 積極的に任せてよい                          │
│  ・概念の説明、比喩を使った解説                 │
│  ・エラーメッセージの意味を訳させる             │
│  ・定型的なコードの雛形（HTMLの構造など）       │
│  ・命名のアイデア出し                          │
│  ・自分のコードのレビュー                      │
│  ・練習問題の作成                              │
│  ・ドキュメントやコメントの下書き               │
├──────────────────────────────────────────────┤
│ ⚠️ 任せてよいが、必ず検証が必要                 │
│  ・具体的な実装コード                          │
│  ・SQL文                                       │
│  ・正規表現                                    │
│  ・ライブラリやツールの選定                     │
│  ・パフォーマンス改善の提案                     │
├──────────────────────────────────────────────┤
│ ❌ 任せてはいけない                            │
│  ・「何を作るか」の意思決定                     │
│  ・セキュリティの最終判断                       │
│  ・個人情報・機密情報を含むコードの貼り付け      │
│  ・APIキー・パスワードを含むコードの貼り付け     │
│  ・業務データそのものの投入                     │
└──────────────────────────────────────────────┘
```

> ⚠️ **APIキーやパスワードを、絶対にAIに貼らないでください。**
> 学習中でも癖をつけないことが大切です。貼る前に、必ず `xxxxx` などに置き換えてください。
> 会社のコードを貼ってよいかは、勤務先のルールに従ってください（レッスン6-7で扱います）。

## 🔧 やってみよう：AIの嘘を見つける演習

以下のプロンプトを、実際にAIに投げてください。

```text
PHPで、文字列を逆順にする関数を教えてください。
また、配列の要素をランダムに並べ替える関数も教えてください。
それぞれ、コード例も示してください。
```

返ってきた関数名を、**すべて php.net で確認**してください。

- 存在した関数：`___________`
- 存在しなかった関数：`___________`

多くの場合は正しく答えますが、**確認する習慣**をつけることが目的です。実在した場合も、公式ドキュメントで**引数と戻り値**を確認してください。AIは関数名は合っていても、**引数の順番を間違える**ことがあります。

### 追加演習

次のコードをAIに渡し、セキュリティレビューをさせてください（STEP 4のテンプレートを使用）。

```php
<?php
$name = $_GET['name'];
$conn = new mysqli("localhost", "root", "", "testdb");
$result = $conn->query("SELECT * FROM users WHERE name = '$name'");
echo "こんにちは、" . $name . "さん";
```

このコードには**2つの重大な脆弱性**があります。AIは指摘できましたか？
（答え：SQLインジェクションとXSS。詳しくは第3部・第4部で学びます）
