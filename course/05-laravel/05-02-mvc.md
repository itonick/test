## 📖 MVC は「役割分担」

第3部の掲示板で、あなたは1つのファイルに全部書きました。

```php
// index.php に、全部が混ざっていた
if ($_SERVER["REQUEST_METHOD"] === "POST") {
    // 入力を受け取る
    // 検証する
    // データベースに保存する（リポジトリ経由）
    // リダイレクトする
}
// データを取得する
// HTMLを組み立てる
```

**規模が大きくなると、この「全部入り」は破綻します。** MVC は、これを3つに分けます。

```
┌─────────────────────────────────────────────────────────┐
│  Model（モデル）     データとビジネスロジック           │
│                      「投稿とは何か」「どう保存するか」  │
│                      → 第3部の PostRepository / Post     │
├─────────────────────────────────────────────────────────┤
│  View（ビュー）      画面の見た目                        │
│                      「どう表示するか」                  │
│                      → 第3部の partials/*.php            │
├─────────────────────────────────────────────────────────┤
│  Controller（コントローラ）  制御の司令塔                │
│                      「リクエストを受けて、Modelを呼び、  │
│                        Viewに渡す」                      │
│                      → 第3部の index.php の分岐部分       │
└─────────────────────────────────────────────────────────┘
```

**第3部で、あなたは無意識にこの分離を始めていました。**
- `Post` / `PostRepository` を分けた → **Model**
- `partials/` に表示を切り出した → **View**
- `index.php` で分岐した → **Controller**

Laravel は、これを**明確な場所とルール**で強制します。

## 📖 リクエストの流れ

**URLを開いてから、画面が表示されるまで**の流れです。

```
① ブラウザ
   GET /items/5
      ↓
② routes/web.php（ルーティング）
   「/items/{id} は ItemController の show メソッドへ」
      ↓
③ app/Http/Controllers/ItemController.php（コントローラ）
   show(5) が呼ばれる
      ↓
④ app/Models/Item.php（モデル）
   Item::find(5) でデータベースから取得
      ↓
   ← 商品データが返る
      ↓
⑤ resources/views/items/show.blade.php（ビュー）
   データを受け取ってHTMLを組み立てる
      ↓
⑥ ブラウザ
   HTMLが表示される
```

| 段階 | 第3部でいうと |
| --- | --- |
| ② ルーティング | `if ($action === "show")` の分岐 |
| ③ コントローラ | その分岐の中の処理 |
| ④ モデル | `PostRepository::find()` |
| ⑤ ビュー | `partials/` の include |

> 💡 **この流れが、Laravel のすべての基本です。**
> どんなに複雑なアプリでも、「ルート → コントローラ → モデル → ビュー」の繰り返しです。
> **迷ったら、この図に立ち返ってください。**

## 📖 ディレクトリ構成を覚える

**全部覚える必要はありません。よく使う場所だけ**を押さえます。

```
flea-market/
│
├─ routes/
│   └─ web.php              ★★★ ルーティング（URLと処理の対応）
│
├─ app/
│   ├─ Models/              ★★★ モデル（Item.php, User.php）
│   │   └─ User.php
│   └─ Http/
│       ├─ Controllers/     ★★★ コントローラ
│       │   └─ Controller.php
│       └─ Requests/        ★★  フォームリクエスト（バリデーション）
│
├─ resources/
│   └─ views/               ★★★ Blade テンプレート
│       └─ welcome.blade.php
│
├─ database/
│   ├─ migrations/          ★★★ テーブル定義
│   ├─ seeders/             ★★  テストデータ
│   └─ factories/           ★   ダミーデータ生成
│
├─ public/                  ★   公開ディレクトリ（画像、CSS）
│   └─ index.php            （触らない。すべての入口）
│
├─ config/                  ★   設定ファイル
├─ storage/
│   ├─ app/                 アップロードファイル
│   └─ logs/                ★★  ログ（laravel.log）
│
├─ .env                     ★★★ 環境設定
└─ artisan                  ★★★ コマンドツール
```

### 特に重要な3つ

| 場所 | 何を書くか |
| --- | --- |
| `routes/web.php` | **どのURLで、どの処理を呼ぶか** |
| `app/Http/Controllers/` | **処理の本体** |
| `resources/views/` | **画面（Blade）** |

**この3つを行き来するのが、Laravel 開発の基本の動き**です。

## ✍️ 手を動かす① ─ 流れを1本作ってみる

**ルート → コントローラ → ビュー**の最小の流れを作ります。

### ① コントローラを作る

```bash
php artisan make:controller HelloController
```

`app/Http/Controllers/HelloController.php` が作られます。

```php
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;

class HelloController extends Controller
{
    public function index()
    {
        $name = "太郎";
        // ビューに $name を渡して表示する
        return view('hello', ['name' => $name]);
    }
}
```

> 🆘 **ここで詰まったら**（`404` や `View [hello] not found` になる）
> - **`404 Not Found`**：`routes/web.php` にルートを書いたか／URLのつづり／`php artisan serve` が動いているか。`php artisan route:list` で登録済みルートを一覧できます
> - **`View [hello] not found`**：`return view('hello')` に対応する **`resources/views/hello.blade.php`** があるか（拡張子は `.blade.php`、ドットはフォルダ区切り＝`items.show` は `views/items/show.blade.php`）
> - **`Target class [HelloController] does not exist`**：コントローラ名のつづり、`use App\Http\Controllers\HelloController;`、名前空間を確認
> - **直らなければ、AIにこう聞く**（web.php・コントローラ・ビューの3つとエラー全文を貼る）：
>   「Laravelでルート→コントローラ→ビューの最小構成を作ったら○○エラーが出ます。原因を確認手順つきで教えてください」

> 💡 **`php artisan make:controller` が、雛形を自動生成します。**
> 第3部では、ファイルを手で作り、`namespace` を手で書きました。
> Laravel は、命名規則に沿った雛形を用意してくれます。

### ② ビューを作る

`resources/views/hello.blade.php` を作ります。

```blade
<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <title>Hello</title>
</head>
<body>
  <h1>こんにちは、{{ $name }}さん</h1>
</body>
</html>
```

> 💡 **`{{ $name }}` は、`<?= e($name) ?>` に相当します。**
> Blade の `{{ }}` は、**自動でエスケープ**してくれます（5-5で詳しく）。
> 第3部で「出力には必ず `e()`」と学びましたが、Blade はそれを標準にしています。

### ③ ルートを定義する

`routes/web.php` に追加します。

```php
<?php

use Illuminate\Support\Facades\Route;
use App\Http\Controllers\HelloController;

Route::get('/', function () {
    return view('welcome');
});

// 追加
Route::get('/hello', [HelloController::class, 'index']);
```

### ④ 確認する

```bash
php artisan serve
```

`http://127.0.0.1:8000/hello` を開くと「こんにちは、太郎さん」が表示されます。

**これが、MVC の1本の流れです。**

```
/hello にアクセス
  → web.php が HelloController@index を呼ぶ（ルート）
  → index() が $name を用意し、view('hello') に渡す（コントローラ）
  → hello.blade.php が {{ $name }} を表示（ビュー）
```

## 📖 名前空間とオートロードの回収

第3部（3-10）で学んだ**名前空間とPSR-4オートロード**が、ここで活きます。

```php
namespace App\Http\Controllers;   // ← app/Http/Controllers/ に対応
```

```php
use App\Http\Controllers\HelloController;   // ← use で読み込む
```

| 名前空間 | ディレクトリ |
| --- | --- |
| `App\Models\Item` | `app/Models/Item.php` |
| `App\Http\Controllers\ItemController` | `app/Http/Controllers/ItemController.php` |
| `App\Http\Requests\StoreItemRequest` | `app/Http/Requests/StoreItemRequest.php` |

**「名前空間 = ディレクトリ」「クラス名 = ファイル名」。**
3-10 で学んだPSR-4のルールが、Laravel の全体を支えています。

> 💡 **`require_once` を1つも書いていない**ことに気づきましたか？
> Composer のオートロードが、クラスを使った瞬間に自動で読み込みます。
> 第3部の最後で仕込んだ知識が、ここで完全に回収されました。

## 📖 「規約」を理解する

Laravel は**「設定より規約（Convention over Configuration）」**という思想です。
**決められた名前・場所に従えば、設定を書かずに動きます。**

| 規約 | 例 |
| --- | --- |
| モデル名は**単数形・PascalCase** | `Item`（テーブルは `items`） |
| モデルは自動で複数形のテーブルを見る | `Item` → `items` |
| コントローラ名は **〜Controller** | `ItemController` |
| ビューは `resources/views/` 以下 | `view('items.show')` → `items/show.blade.php` |
| 外部キーは **`単数形_id`** | `user_id` |
| 主キーは **`id`** | — |

**これは第4部（4-5）で学んだ命名規則と、まったく同じです。**
あなたが学んだ規則は、Laravel の規約そのものでした。

> ⚠️ **規約から外れると、追加の設定が必要になります。**
> 例：`Item` モデルが `products` テーブルを見たいなら、
> `protected $table = 'products';` と明示します。
> **規約に従えば、こういう設定を書かずに済みます。**

## ⚠️ つまずきポイントまとめ

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `View [hello] not found` | ビューのファイル名・場所が違う | `resources/views/hello.blade.php` |
| `Class HelloController not found` | `use` の書き忘れ | ルートで `use App\Http\Controllers\...` |
| `Target class does not exist` | コントローラ名のタイプミス | クラス名を確認 |
| ルートが 404 | `web.php` に定義されていない | ルートを追加。`php artisan route:list` で確認 |
| 変更が反映されない | ルートキャッシュ | `php artisan route:clear` |
| `{{ $name }}` がそのまま出る | Blade でないファイル | 拡張子を `.blade.php` に |

### `route:list` でルートを確認する

```bash
php artisan route:list
```

```
GET|HEAD   /              ...
GET|HEAD   hello          HelloController@index
```

**「どのURLが、どの処理に対応しているか」の一覧**です。
第4部までの掲示板では自分で分岐を追いましたが、Laravel では一覧で見られます。
