## 📖 パスがわかれば、事故の8割は防げる

初学者が最も多く踏む地雷が「**画像が表示されない**」です。原因はほぼ100%、**パスの書き方**です。

パスとは「ファイルの居場所の書き方」のこと。2種類あります。

| 種類 | 例 | 意味 |
| --- | --- | --- |
| **絶対パス** | `https://example.com/img/a.png` | インターネット上の完全な住所 |
| **ルート相対パス** | `/images/a.png` | サイトの一番上（ルート）から見た場所 |
| **相対パス** | `images/a.png` | **いま書いているHTMLファイル**から見た場所 |

**学習中は相対パスを使います。** 理由は、ルート相対パスはサーバー設定に依存し、ローカルで動かないことがあるからです。

### 相対パスの3つの書き方

いま `htdocs/komorebi/index.html` を書いているとします。

```
htdocs/
└─ komorebi/
   ├─ index.html      ← いまここ
   ├─ css/
   │   └─ style.css
   ├─ images/
   │   └─ hero.jpg
   └─ pages/
       └─ menu.html
```

| 書き方 | 意味 | 例 |
| --- | --- | --- |
| `images/hero.jpg` | **同じ階層**の images フォルダの中 | ✅ よく使う |
| `./images/hero.jpg` | 上と同じ（`./` は「ここ」の意味。省略可） | 同じ |
| `../index.html` | **1つ上**の階層へ | `pages/menu.html` から index.html を指すとき |

> 💡 **`../` は「1つ上のフォルダへ」。** 2つ上なら `../../`。
> エレベーターで階を上がるイメージです。

### つまずきポイント：どこから見たパスか

```
pages/menu.html から images/hero.jpg を指したい
```

`menu.html` は `pages/` の中にいます。`images/` は `pages/` の**外**（1つ上）にあります。

```html
<!-- ❌ pages/ の中に images/ を探しに行ってしまう -->
<img src="images/hero.jpg" alt="">

<!-- ✅ 1つ上に戻ってから images/ へ -->
<img src="../images/hero.jpg" alt="">
```

> ⚠️ **パスは「HTMLファイルの場所」を起点にします。**
> 「ブラウザで表示しているURL」でも「プロジェクトのルート」でもありません。**そのHTMLファイルがどこにいるか**です。
> ここを取り違えるのが、画像が出ない原因の第1位です。

## ✍️ 手を動かす① ─ 画像を用意する

### 画像の準備

`komorebi/images/` フォルダに、以下の4枚を用意してください。

| ファイル名 | 内容 | 推奨サイズ |
| --- | --- | --- |
| `hero.jpg` | ヒーロー画像（店内やコーヒー） | 1600 × 900 |
| `menu-drip.jpg` | ハンドドリップ | 800 × 800 |
| `menu-latte.jpg` | カフェラテ | 800 × 800 |
| `menu-cake.jpg` | ケーキ | 800 × 800 |

**画像が手元にない場合**、以下の無料素材サイトから商用利用可の写真をダウンロードしてください。

- Unsplash（https://unsplash.com/ja ）
- Pexels（https://www.pexels.com/ja-jp/ ）
- 写真AC（https://www.photo-ac.com/ ）

> 💡 検索キーワード：`coffee shop` `cafe latte` `hand drip`

> ⚠️ **ファイル名に日本語やスペースを使わないでください。**
> `コーヒー 写真.jpg` のような名前は、環境によって表示できません。
> **半角英数字とハイフンだけ**にするのが鉄則です。

### 画像を軽くする

ダウンロードした写真は数MBあることが多く、そのまま使うとページが重くなります。

無料の圧縮サービスを使ってください。

- **Squoosh**（https://squoosh.app/ ）— Google製。ブラウザ上で完結
- **TinyPNG**（https://tinypng.com/ ）— ドラッグ&ドロップで圧縮

**目安：1枚 200KB 以下。** ヒーロー画像でも 400KB を超えないようにします。

## ✍️ 手を動かす② ─ `<img>` の書き方

### 基本形

```html
<img src="images/hero.jpg" alt="窓辺の席に差し込む木漏れ日とコーヒーカップ" width="1600" height="900">
```

| 属性 | 必須 | 役割 |
| --- | --- | --- |
| `src` | **必須** | 画像のパス |
| `alt` | **必須** | 画像の代替テキスト |
| `width` / `height` | 推奨 | 元画像の**ピクセル数**。レイアウトのガタつきを防ぐ |
| `loading="lazy"` | 推奨 | 画面外の画像を後回しで読み込む（表示が速くなる） |

> 🆘 **ここで詰まったら**（画像が表示されず、枠や alt の文字だけ出る）
> - **まず確認**：① `src` のパスは合っているか（`images/` の付け忘れ、大文字小文字、`.jpg` と `.JPG` の違い）② 画像ファイルは本当にその場所にあるか ③ 開発者ツール（F12）の「Network」タブで、その画像が**赤い404**になっていないか
> - **切り分けのコツ**：`src` に確実に存在する別画像やフルパスを入れて出るか試すと、「パスの問題」か「画像自体の問題」かが分かります
> - **直らなければ、AIにこう聞く**（HTMLの該当行とフォルダ構成を貼る）：
>   「画像が表示されません。src のパスは合っているつもりです。他に考えられる原因を、確認手順つきで教えてください」

### `alt` の書き方が意外と難しい

`alt` は、画像が表示できないときに代わりに読まれる文章です。スクリーンリーダーもこれを読み上げます。

| 画像の役割 | `alt` の書き方 | 例 |
| --- | --- | --- |
| 内容を伝える写真 | **何が写っているかを説明** | `alt="窓辺の席に差し込む木漏れ日とコーヒーカップ"` |
| ロゴ | **企業名・店名** | `alt="KOMOREBI COFFEE"` |
| リンクになっている画像 | **リンク先が何か** | `alt="メニュー一覧を見る"` |
| 装飾だけの画像 | **空にする**（属性は書く） | `alt=""` |

> ⚠️ **やってはいけない `alt`**
> - `alt="画像"` `alt="写真"` — 情報がゼロ。無いのと同じ
> - `alt="hero.jpg"` — ファイル名は読み手に無意味
> - `alt` を書かない — スクリーンリーダーがファイル名を読み上げてしまう
>
> **装飾画像なら `alt=""`（空）が正解**です。空にすることで「読み飛ばしてよい」と伝わります。

### `width` / `height` を書く理由

```html
<!-- ❌ 書かない場合 -->
<img src="images/hero.jpg" alt="...">
```

画像が読み込まれるまでブラウザは高さを知らないため、**読み込んだ瞬間にページがガクッとずれます**。これを **CLS（レイアウトシフト）** と呼び、ユーザー体験を大きく損ないます。

```html
<!-- ✅ 元画像のピクセル数を書く -->
<img src="images/hero.jpg" alt="..." width="1600" height="900">
```

これで、ブラウザは読み込み前に場所を確保できます。

> 💡 CSSで `width: 100%` にしても構いません。HTMLの `width`/`height` は**縦横比を伝えるため**のものなので、両方書いて矛盾しません。

## ✍️ 手を動かす③ ─ カフェLPを育てる

`index.html` の `<main>` の中を、以下のように書き換えてください。

> 🖊 **手で打ってください。** 完成形は `code/01-03/index.html` にあります（📋 コピペ可）。

```html
  <main>

    <section class="hero">
      <img src="images/hero.jpg"
           alt="窓辺の席に差し込む木漏れ日とコーヒーカップ"
           width="1600" height="900">
      <h1>木漏れ日の下で、一杯を。</h1>
      <p>住宅街の小さな自家焙煎コーヒースタンド。</p>
      <a href="#menu" class="btn">メニューを見る</a>
    </section>

    <section id="menu" class="menu">
      <h2>MENU</h2>
      <p>季節ごとに、産地を変えてお出ししています。</p>

      <ul class="menu-list">
        <li class="menu-item">
          <img src="images/menu-drip.jpg" alt="ドリッパーから注がれるコーヒー"
               width="800" height="800" loading="lazy">
          <h3>ハンドドリップ</h3>
          <p class="price">¥600</p>
          <p>その日の豆から、お好みの一杯を選べます。</p>
        </li>

        <li class="menu-item">
          <img src="images/menu-latte.jpg" alt="ラテアートの施されたカフェラテ"
               width="800" height="800" loading="lazy">
          <h3>カフェラテ</h3>
          <p class="price">¥600</p>
          <p>深煎りの豆と、きめ細かいミルクで。</p>
        </li>

        <li class="menu-item">
          <img src="images/menu-cake.jpg" alt="皿に盛り付けられたチーズケーキ"
               width="800" height="800" loading="lazy">
          <h3>本日のケーキ</h3>
          <p class="price">¥550</p>
          <p>近所の焼き菓子店から、毎朝届きます。</p>
        </li>
      </ul>
    </section>

    <section id="about" class="about">
      <h2>ABOUT</h2>
      <p>2019年、この街で焙煎を始めました。豆は月替わりで、
         小さなロースターから直接仕入れています。</p>
    </section>

    <section id="access" class="access">
      <h2>ACCESS</h2>
      <dl class="info">
        <dt>住所</dt>
        <dd>東京都〇〇区〇〇 1-2-3</dd>
        <dt>営業時間</dt>
        <dd>8:00 - 18:00</dd>
        <dt>定休日</dt>
        <dd>水曜日</dd>
        <dt>電話</dt>
        <dd><a href="tel:0312345678">03-1234-5678</a></dd>
      </dl>
    </section>

  </main>
```

### 新しく出てきたもの

| 書いたもの | 意味 |
| --- | --- |
| `<ul class="menu-list">` | メニューは「商品のリスト」なので `<ul>` が適切 |
| `<dl> <dt> <dd>` | **定義リスト**。「項目名と値」のペアに使う |
| `<a href="tel:...">` | スマホでタップすると電話が発信される |
| `loading="lazy"` | 画面外の画像を遅延読み込み。ヒーロー画像には付けない |

### `<dl>` の使いどころ

```html
<dl>
  <dt>住所</dt>            <!-- dt = 項目名（Definition Term） -->
  <dd>東京都〇〇区...</dd>  <!-- dd = 値（Definition Description） -->
</dl>
```

住所・営業時間・スペック表など、**「ラベルと値」の組み合わせ**には `<dl>` が最適です。`<table>` を使う人が多いですが、表（行列）ではないので `<dl>` が正解です。

## ✍️ 手を動かす④ ─ リンクの種類を押さえる

```html
<!-- 別ページへ（相対パス） -->
<a href="pages/menu.html">メニュー詳細</a>

<!-- 外部サイトへ（絶対パス）※新しいタブで開く -->
<a href="https://www.instagram.com/" target="_blank" rel="noopener">Instagram</a>

<!-- ページ内へ -->
<a href="#menu">メニューへ</a>

<!-- メール -->
<a href="mailto:info@example.com">お問い合わせ</a>

<!-- 電話（スマホでタップ発信） -->
<a href="tel:0312345678">03-1234-5678</a>

<!-- ファイルのダウンロード -->
<a href="files/menu.pdf" download>メニューPDF</a>
```

> ⚠️ **`target="_blank"` には必ず `rel="noopener"` を付ける。**
> 付けないと、リンク先のページから元のページを操作できてしまう脆弱性（tabnabbing）が生じます。
> セットで書く、と体で覚えてください。

> 💡 **外部リンクだけを新しいタブで開く**のが一般的な作法です。サイト内リンクを `_blank` にすると、タブが増え続けてユーザーに嫌がられます。

## ⚠️ つまずきポイントまとめ ─ 画像が表示されないとき

**チェックリスト（上から順に確認）**

```
1. Chrome の開発者ツール → Network タブを開いてリロード
   → 画像の行が「404」になっていないか？
      404 なら → パスかファイル名の問題（下記2〜5へ）
      404 でない → 画像自体が壊れている可能性

2. ファイル名のつづりは合っているか？
   → 大文字小文字も区別される（Hero.jpg と hero.jpg は別物）

3. 拡張子は合っているか？
   → .jpg と .jpeg は別。実際のファイルを確認

4. フォルダの階層は合っているか？
   → HTMLファイルから見た相対パスになっているか

5. ファイル名に日本語・スペースが入っていないか？

6. 画像ファイルは本当にそこにあるか？
   → VS Code のエクスプローラーで実際に確認する
```

> 💡 **最速の確認方法**：VS Code で `src="` まで打つと、**パスの候補が自動補完**されます。
> 補完に出てこないパスは、存在しないパスです。手打ちせず補完を使ってください。

### その他のつまずき

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 画像が巨大に表示される | CSSがまだないので原寸表示される | 正常。レッスン1-5でCSSを当てます |
| 画像の下に謎の隙間ができる | `<img>` はインライン要素で、行の下に余白ができる | CSSで `display: block` を指定（1-6で扱います） |
| ページが重い | 画像を圧縮していない | Squoosh で圧縮する |
| リンクをクリックすると何も起きない | `href` の書き忘れ | `<a>` には必ず `href` を書く |
