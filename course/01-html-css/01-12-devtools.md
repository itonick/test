# 1-12 開発者ツールでCSSをデバッグする

> 🎯 **このレッスンのゴール**
> - 開発者ツールの5つのパネルを使い分けられる
> - 「効かないCSS」を、推測ではなく**証拠で**特定できる
> - ブラウザ上で試してからコードに書く、という手順を身につける

所要 90分 / 難度 🟡

---

## 📖 なぜこのレッスンを独立させるのか

初学者とプロの最大の差は、**知識量ではなく「原因を特定する速さ」**です。

```
初学者：CSSを書き換える → 効かない → 別の書き方を試す → 効かない → 検索する
        （推測ベース。運が悪いと1時間溶ける）

プロ：  開発者ツールで要素を選択 → 打ち消し線を見つける → 詳細度を上げる
        （証拠ベース。30秒）
```

**この差は、ツールを知っているかどうかだけです。** このレッスンで埋めます。

---

## ✍️ 手を動かす① ─ 開き方と全体像

| 操作 | Windows | Mac |
| --- | --- | --- |
| 開発者ツールを開く | `F12` または `Ctrl + Shift + I` | `Cmd + Option + I` |
| 要素を選択して開く | 右クリック →「検証」 | 右クリック →「検証」 |
| 要素選択モード | `Ctrl + Shift + C` | `Cmd + Shift + C` |
| デバイスモード | `Ctrl + Shift + M` | `Cmd + Shift + M` |
| コンソールを開く | `Esc`（他パネル表示中） | `Esc` |

### 使うパネルは5つ

| パネル | 何ができるか | 使用頻度 |
| --- | --- | --- |
| **Elements** | HTML構造とCSSの確認・編集 | ★★★ |
| **Console** | JavaScriptのエラー・ログ | ★★★（第2部から） |
| **Network** | ファイルの読み込み状況（404など） | ★★★ |
| **Sources** | ソースコードの確認・ブレークポイント | ★★（第2部から） |
| **Lighthouse** | 表示速度・SEO・アクセシビリティの採点 | ★（仕上げ時） |

## ✍️ 手を動かす② ─ Elements パネル（主戦場）

### 要素を選ぶ

1. `Ctrl + Shift + C` で**要素選択モード**にする
2. 画面上の調べたい要素をクリック
3. HTMLの該当箇所がハイライトされる

### 右側の「Styles」を読む

```
element.style {
}

.menu-item h3 {                      ← このセレクタが当たっている
  font-size: var(--fs-lg);           ← 適用されている
  margin-bottom: 2px;
}

h1, h2, h3 {
  line-height: 1.4;
  font-weight: 700;
  ~~font-size: 18px;~~               ← 打ち消し線 = 負けている
}
```

**読み方の3ポイント**

| 見るもの | わかること |
| --- | --- |
| **上にあるルールほど強い** | 詳細度順に並んでいる |
| **打ち消し線** | そのプロパティは負けている |
| **右端のファイル名:行数** | どのCSSファイルの何行目か（クリックで飛べる） |

> 💡 **「CSSが効かない」の9割は、ここで打ち消し線を探すだけで解決します。**
> 打ち消し線があれば詳細度の問題、そもそもルールが表示されないならセレクタが間違っています。

### その場で編集する

- **値をクリック**して書き換えられる
- **↑ / ↓ キー**で数値が1ずつ変化（`Shift + ↑` で10ずつ）
- **チェックボックス**でプロパティを一時的に無効化
- **`.cls` ボタン**でクラスを一時的に追加・削除
- **`:hov` ボタン**で `:hover` `:focus` 状態を強制表示

> 💡 **`:hov` は非常に便利です。**
> ホバー時のスタイルを調整するのに、いちいちマウスを乗せ続ける必要がなくなります。
> ドロップダウンメニューのデバッグでは必須です。

### 空のルールを追加する

`element.style { }` の中に直接書けば、そのままインラインスタイルとして試せます。
また、`+` ボタンで新しいルールを追加できます。

> **ワークフロー**：ブラウザで値を調整して見た目を決める → **決まった値をCSSファイルに書き写す**
> これがプロの手順です。エディタで書いて保存して確認、を繰り返すより圧倒的に速いです。

> ⚠️ **開発者ツールでの編集は、リロードすると消えます。** 良い値が決まったら、必ずCSSファイルに書き写してください。

### Computed タブ

「最終的に適用された値」を見られます。

- `var(--fs-lg)` が実際に何pxになったか
- 継承された値がいくつか
- プロパティ名の左の ▶ を開くと、**どのルールから来た値か**がわかる

> 💡 カスタムプロパティを使っていると Styles だけでは実値がわかりません。**Computed で確認**します。

### ボックスモデル図

Styles パネルの下部（または Computed の上部）にあります。

```
┌───── margin ─────────────┐
│  ┌── border ──────────┐  │
│  │ ┌─ padding ──────┐ │  │
│  │ │   288 × 42     │ │  │
│  │ └────────────────┘ │  │
│  └────────────────────┘  │
└──────────────────────────┘
```

- 各数値を**ダブルクリックで編集**できる
- 図にマウスを乗せると、画面上の該当領域が色分けされる

**余白の問題は、必ずここを見てください。**

## ✍️ 手を動かす③ ─ レイアウトのデバッグ

### Flexbox / Grid バッジ

`display: flex` または `display: grid` の要素には、HTMLの横に **`flex` / `grid` のバッジ**が出ます。

クリックすると、画面上に以下が重ねて表示されます。

| Flex | Grid |
| --- | --- |
| 主軸・交差軸の方向 | グリッド線と線番号 |
| 各アイテムの領域 | エリア名 |
| gap の領域 | gap の領域 |

**Elements パネル下部の「Layout」タブ**で、表示方法をカスタマイズできます（線番号の表示、常時表示など）。

> 💡 Flexbox / Grid で悩んだら、まずバッジをオンにしてください。**頭で考えるより速いです。**

### はみ出し要素を探す

横スクロールが出るとき、**Console** に以下を貼って実行すると、はみ出している要素が列挙されます。

```javascript
document.querySelectorAll('*').forEach(el => {
  if (el.getBoundingClientRect().right > document.documentElement.clientWidth) {
    console.log(el);
  }
});
```

> 💡 これは第2部の内容を先取りしていますが、**コピペで使える便利ツール**として覚えておいてください。
> 出力された要素にマウスを乗せると、画面上でハイライトされます。

## ✍️ 手を動かす④ ─ Network パネル

### 見るべきは3つ

| 列 | 見るポイント |
| --- | --- |
| **Status** | `200` = OK、`404` = ファイルがない、`304` = キャッシュ |
| **Name** | ファイル名 |
| **Size** | ファイルサイズ（重すぎないか） |

### 使い方

1. Network タブを開く
2. **ページをリロード**（開いてから開くと何も出ません）
3. 上部の **CSS / Img / JS** でフィルタ

**確認すること**

- [ ] `style.css` が `200` で読み込まれているか（`404` なら パスが違う）
- [ ] 画像が全部 `200` か
- [ ] 極端に重いファイルがないか（画像は 200KB 以下が目安）
- [ ] Webフォントが読み込まれているか

### キャッシュを無効にする

Network タブの **「Disable cache」にチェック**を入れると、開発者ツールを開いている間は常に最新が読み込まれます。

> 💡 **開発中は常にオンにしておいてください。** 「直したのに反映されない」の大半が防げます。

## ✍️ 手を動かす⑤ ─ デバイスモードとアクセシビリティ

### デバイスモード（`Ctrl + Shift + M`）

- 上部で端末を選択、または幅を直接入力
- 「Responsive」を選ぶと、**ドラッグで幅を連続的に変えられる**
- 回転ボタンで縦横切り替え
- **Throttling** で低速回線をシミュレートできる

> 💡 **幅をドラッグしながらゆっくり動かす**と、レイアウトが崩れる正確な幅がわかります。それがブレークポイントの候補です。

### アクセシビリティの確認

Elements パネルの下部に **Accessibility** タブがあります。

- **Name**：スクリーンリーダーが読み上げる名前
- **Role**：要素の役割（button、link、heading など）
- **Contrast**：文字色と背景色のコントラスト比

**確認してほしいこと**

- [ ] 画像の Name に、意味のある `alt` が入っているか
- [ ] ボタンやリンクの Name が空でないか
- [ ] フォームの入力欄に、`label` の文字が Name として出ているか

### Lighthouse で採点する

1. **Lighthouse** タブを開く
2. カテゴリを選択（Performance / Accessibility / Best Practices / SEO）
3. 「Analyze page load」をクリック

**100点満点で採点され、改善案が具体的に出ます。**

> 💡 **Accessibility と SEO は、いま作っているLPでも 90点以上を狙えます。**
> Performance は画像サイズに大きく左右されるので、画像を圧縮してから測ってください。
>
> ⚠️ ローカル環境（`localhost`）での測定値は、本番と異なります。傾向をつかむ目的で使ってください。

## ✍️ 手を動かす⑥ ─ 実践：カフェLPを診断する

自分のカフェLPで、以下を1つずつ確認してください。

### チェックリスト

**Elements**
- [ ] `.hero-copy` を選択し、`position: absolute` が効いていることを確認
- [ ] `.menu-list` の `grid` バッジをオンにし、列がどう分割されているか見る
- [ ] `.btn` を選択し、`:hov` で hover 状態を強制表示して色を確認
- [ ] `main > section` のボックスモデル図で、`padding-block` の実際の値を確認

**Computed**
- [ ] `.hero h1` の `font-size` が、`clamp()` の結果として実際に何pxになっているか確認
- [ ] ウィンドウ幅を変えながら、その値が変化することを確認

**Network**
- [ ] リロードして、404 のファイルが1つもないことを確認
- [ ] 画像のサイズを確認し、200KBを超えているものがあれば圧縮する

**デバイスモード**
- [ ] 320px で横スクロールが出ないことを確認
- [ ] 幅をドラッグで動かし、崩れる箇所がないか確認

**Lighthouse**
- [ ] Accessibility を測定し、指摘があれば内容を読む
- [ ] SEO を測定し、90点以上か確認

## ⚠️ つまずきポイントまとめ

| 症状 | 開発者ツールでの確認方法 |
| --- | --- |
| CSSが全く効かない | **Network** で `style.css` が 404 でないか |
| CSSが一部効かない | **Elements → Styles** で打ち消し線を探す |
| セレクタが合っているかわからない | Styles にそのルールが**表示されるか** |
| 変数の実値がわからない | **Computed** タブで確認 |
| 余白がおかしい | **ボックスモデル図**で実測値を見る |
| Flex/Grid が思い通りにならない | **バッジ**をオンにして可視化 |
| 画像が出ない | **Network** で 404 を確認 |
| 横スクロールが出る | Console のスニペットではみ出し要素を列挙 |
| ホバーの見た目を調整したい | **`:hov`** で状態を固定 |
| 変更が反映されない | Network の **Disable cache** をオン |

## 🤖 AIに聞いてみよう

### ① Lighthouse の指摘を解読させる

```text
Lighthouse でWebページを診断したところ、以下の指摘が出ました。

（指摘の内容をコピペ）

初学者向けに、以下を教えてください。

1. この指摘は何を問題視しているのか
2. 放置するとどんな不都合があるのか
3. 優先度は高いか低いか
4. 修正するための考え方（コードではなく方針）

すぐに修正コードを出すのではなく、私が自分で直せるよう説明してください。
```

### ② デバッグ手順そのものを教わる

```text
CSSのデバッグ手順を体系的に身につけたいです。

以下の症状それぞれについて、Chrome の開発者ツールを使った
「確認手順」を、上から順に教えてください。

1. 指定したCSSが効かない
2. 要素の余白が思った通りにならない
3. Flexbox で横並びにならない
4. スマホ幅で横スクロールが出る
5. z-index が効かない

各手順で「何を見て、何が確認できたら次に進むか」を明示してください。
コードによる解決策ではなく、原因特定の手順を知りたいです。
```

> 💡 この回答は保存して、**自分専用のデバッグ手順書**にしてください。

## 🔧 やってみよう（演習）

**AIに頼らず、自力でやってください。**

### 演習1（必須）─ 壊して直す

自分のカフェLPで、以下を**わざと壊して**、開発者ツールで原因を特定してください。

| 壊し方 | 特定に使うパネル |
| --- | --- |
| `<link>` の `href` を `css/styl.css` に変える | Network |
| `.menu-list` のセレクタを `.menu-lists` に変える | Elements（ルールが出ない） |
| `.btn` に `color: red !important;` を別ルールで追加 | Elements（打ち消し線） |
| `img { max-width: 100% }` をコメントアウト | デバイスモード（横スクロール） |

**それぞれ、開発者ツールのどこを見れば気づけるかをメモしてください。**

### 演習2（必須）

以下の症状の原因を、開発者ツールで特定する手順を書いてください（実際に試さなくてもOK）。

1. ボタンにマウスを乗せても色が変わらない
2. カードの高さが揃わない
3. Webフォントが適用されていない気がする
4. ページの読み込みが遅い

<details>
<summary>答えを見る</summary>

1. **Elements → `:hov` で `:hover` を強制** → ルールが表示されるか確認 → 表示されるなら打ち消し線を探す / 表示されないならセレクタのミス
2. **Elements → 親の `flex` バッジをオン** → `align-items` の値を確認（`stretch` になっているか）
3. **Elements → Computed で `font-family` の実値を確認** → 意図したフォント名が先頭に来ているか。次に **Network → Font** フィルタで、フォントファイルが 200 で読み込まれているか
4. **Network → Size 列でソート** → 重いファイルを特定。多くの場合は画像。**Lighthouse → Performance** でも具体的な指摘が得られる

</details>

### 演習3（挑戦）

**開発者ツールだけで**、カフェLPを別デザインに変えてみてください（ファイルは編集しない）。

- [ ] `:root` の `--color-accent` を、緑系の色に変える
- [ ] `--font-en` を別のフォントに変える
- [ ] `.hero-media img` の `aspect-ratio` を `1/1` に変える
- [ ] `.menu-list` の `minmax` の最小値を `180px` に変えて、列数が増えることを確認

**気に入った値が見つかったら、それをCSSファイルに書き写してください。**

> 💡 これが「ブラウザで試してからコードに書く」というプロのワークフローです。
> エディタで書く → 保存 → ブラウザ確認 のループより、圧倒的に速く正確です。
