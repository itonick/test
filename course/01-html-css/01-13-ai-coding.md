# 1-13 AIにデザインカンプを実装させる

> 🎯 **このレッスンのゴール**
> - デザインを「AIが理解できる言葉」に翻訳できる
> - AIが出したCSSを、レビューして採否を判断できる
> - AIに任せてよい範囲／自分でやるべき範囲を、CSSの文脈で線引きできる

所要 90分 / 難度 🟡

---

## 📖 ここまでで、あなたは判断できる側になった

第0部で「AIを疑う技術」を学びましたが、当時はまだ**判断材料がありませんでした**。

いまは違います。あなたは以下を知っています。

- ボックスモデルと `box-sizing`
- Flexbox と Grid の使い分け
- 詳細度と `!important` の害
- モバイルファーストと `clamp()`
- 開発者ツールでの検証方法

**この知識があるから、AIの出力を採点できます。** このレッスンは、それを実際にやってみる回です。

---

## 📖 AIにCSSを書かせるときの現実

AIはCSSが得意です。ただし、**次のような癖**があります。

| AIの癖 | 具体例 | 害 |
| --- | --- | --- |
| **古い手法を出す** | `float` でのレイアウト、`clearfix` | 現代のCSSでは不要 |
| **`!important` を安易に使う** | 詳細度の問題を力技で解決 | 保守不能になる |
| **メディアクエリを書きすぎる** | 4〜5個のブレークポイント | `clamp()` や `auto-fit` で済む |
| **ベンダープレフィックスを付けすぎる** | `-webkit-` `-moz-` を全部 | 現代のブラウザには不要 |
| **固定値を多用する** | `width: 1200px` | レスポンシブで壊れる |
| **アクセシビリティを忘れる** | `outline: none` | キーボード操作が不能に |
| **命名がバラバラ** | `.card` `.cardTitle` `.card_body` が混在 | 読みにくい |

> 💡 これらは**あなたが指摘できるレベル**の問題です。第1部を終えた時点で、AIのCSSレビューは十分にできます。

## ✍️ 手を動かす① ─ デザインを言葉にする

AIはあなたの頭の中のデザインを見られません。**言語化の精度が、出力の質を決めます。**

### ダメな指示

```text
おしゃれなカフェのLPを作って
```

→ 一般的で無難な、どこかで見たようなものが出てきます。

### 効く指示のフレームワーク

```text
【何を作るか】
架空のカフェ「KOMOREBI COFFEE」のランディングページの
「MENUセクション」のCSSを書いてください。

【HTML構造】（変更しないでください）
（実際のHTMLを貼る）

【デザインの意図】
- 落ち着いた、木と光の雰囲気
- 情報量は少なく、余白を大きく取る
- 写真が主役、文字は控えめ

【具体的な指定】
- カードは画面幅に応じて 1〜3列（240px を下回らない）
- 画像は正方形、はみ出しは切り取る
- 商品名の下に価格、その下に説明文
- カード同士の間隔は 32px 程度
- ホバー時に画像がわずかに拡大する（0.3秒）

【技術的な制約】
- CSS Grid を使う（Flexbox ではなく）
- メディアクエリは使わず、auto-fit で対応する
- 既存のカスタムプロパティを使う:
  --color-accent, --color-text-light, --fs-lg, --fs-sm
- !important は使わない
- prefers-reduced-motion に対応する

【出力形式】
- CSSのみ（HTMLは変更しない）
- 各ブロックに、何をしているかのコメントを付ける
```

**5つのブロック（何を / 構造 / 意図 / 具体指定 / 制約）**で書くと、精度が跳ね上がります。

> 💡 **「技術的な制約」が最も効きます。**
> ここを書かないと、AIは float を使ったり `!important` を撒いたりします。
> **自分が学んだ手法を制約として明示する**——これが、学習中の正しいAI活用です。

## ✍️ 手を動かす② ─ 実際に投げてレビューする

### ステップ1：AIに書かせる

上のプロンプトを、実際にAIに投げてください。HTMLは自分のカフェLPのメニュー部分を使います。

### ステップ2：採点する

返ってきたCSSを、**以下のチェックリストで採点**してください。

**構文・設計**
- [ ] `display: grid` は親に書かれているか
- [ ] `repeat(auto-fit, minmax(...))` が使われているか
- [ ] `minmax` の最小値が `min(100%, 240px)` になっているか（極小画面対策）
- [ ] `%` ではなく `fr` が使われているか
- [ ] 指定したカスタムプロパティを使っているか

**やってはいけないことをしていないか**
- [ ] `!important` が使われていないか
- [ ] `float` が使われていないか
- [ ] 不要なベンダープレフィックスがないか
- [ ] `outline: none` を書いていないか
- [ ] 固定 `width: ○○px` でレスポンシブが壊れないか

**指示を守っているか**
- [ ] メディアクエリを使っていないか（使うなと指示した）
- [ ] `prefers-reduced-motion` に対応しているか
- [ ] コメントが付いているか

**画像の扱い**
- [ ] `aspect-ratio` と `object-fit: cover` が使われているか
- [ ] ホバーの拡大で、画像が枠からはみ出さないよう `overflow: hidden` があるか

> 🆘 **ここで詰まったら**（AIが出したCSSを貼っても、自分のページに効かない）
> - **最頻出の原因**：AIは**あなたのHTMLのクラス名を知りません**。`.card` を前提に書かれたCSSでも、あなたのHTMLが `.menu-item` なら当たりません
> - **やること**：AIに渡すとき、**自分のHTMLをそのまま貼り**、「このHTMLの**実際のクラス名に合わせて**CSSを書いて」と明示する。または、返ってきたセレクタを自分のクラス名に置き換える
> - **こう頼み直す**：
>   「先ほどのCSSが効きませんでした。私の実際のHTMLはこれです（貼る）。このHTMLのクラス名・構造に合わせて、セレクタを直してください」

### ステップ3：自分の言葉で説明する

**採用する前に、全行を自分の言葉で説明できるか確認してください。**

説明できない行があったら、そこだけ質問します。

```text
いただいたCSSの、以下の行の意味がわかりません。

（該当行を貼る）

1. この行は何をしていますか？
2. この行がないとどうなりますか？
3. 他の書き方はありますか？あるなら、なぜこの書き方を選んだのですか？
```

### ステップ4：検証する

**必ず自分の環境で動かしてください。**

- [ ] 320px で横スクロールが出ないか
- [ ] 768px、1440px で意図通りか
- [ ] 開発者ツールで grid バッジを表示し、列数が想定通りか
- [ ] ホバーが滑らかか、はみ出しがないか
- [ ] キーボードの Tab で操作したとき、フォーカスが見えるか

> ⚠️ **「AIが書いたから正しい」は通用しません。** 動かして確かめるまでは、仮説です。

## ✍️ 手を動かす③ ─ 期待される出力の例

参考として、上のプロンプトに対する**良い回答の例**を示します。自分が受け取ったものと比べてください。

```css
/* ==========================================================
   MENU セクション
   ========================================================== */

/* カード一覧：auto-fit で列数を自動調整（メディアクエリ不要）
   min(100%, 240px) にすることで、極小画面でも横にはみ出さない */
.menu-list {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 240px), 1fr));
  gap: 32px;
  margin-top: 40px;
}

/* サムネイル：画像のホバー拡大がはみ出さないよう overflow を切る */
.menu-thumb {
  position: relative;
  overflow: hidden;
  margin-bottom: 16px;
}

/* 画像は正方形に統一。cover ではみ出し部分を切り取る */
.menu-thumb img {
  width: 100%;
  aspect-ratio: 1 / 1;
  object-fit: cover;
  transition: transform .3s ease;
}

/* ホバーでわずかに拡大 */
.menu-item:hover .menu-thumb img {
  transform: scale(1.04);
}

/* アニメーションを控える設定のユーザーには動かさない */
@media (prefers-reduced-motion: reduce) {
  .menu-thumb img { transition: none; }
  .menu-item:hover .menu-thumb img { transform: none; }
}

.menu-item h3 {
  font-size: var(--fs-lg);
  margin-bottom: 2px;
}

.menu-item .price {
  color: var(--color-accent);
  margin-bottom: 8px;
}

.menu-item p {
  font-size: var(--fs-sm);
  color: var(--color-text-light);
  max-width: 28em;
}
```

### この回答が良い理由

| ポイント | 理由 |
| --- | --- |
| `min(100%, 240px)` | 極小画面での横スクロールを防いでいる |
| `overflow: hidden` | 拡大時のはみ出しを防いでいる（**これを忘れる回答が多い**） |
| `transition` は画像に、`transform` はホバー時に | 分離が正しい |
| `prefers-reduced-motion` 対応 | 指示を守っている |
| カスタムプロパティを使用 | 既存の設計に馴染む |
| コメントが「何を」でなく「なぜ」 | 読む価値がある |

> 💡 **`overflow: hidden` の有無は、良い回答かどうかの分かれ目です。**
> これがないと、ホバー時に画像が隣のカードにはみ出します。あなたはこれを指摘できますか？

## ✍️ 手を動かす④ ─ AIに任せてよい範囲（CSS編）

```
┌──────────────────────────────────────────────┐
│ ✅ 積極的に任せてよい                          │
│  ・リセットCSSの生成                           │
│  ・定型的なコンポーネント（ボタン、カード）     │
│  ・アニメーションの keyframes                  │
│  ・複雑な calc() や clamp() の計算              │
│  ・クロスブラウザ対応の調査                     │
│  ・自分のCSSのレビュー                         │
│  ・命名（BEMなど）の提案                       │
├──────────────────────────────────────────────┤
│ ⚠️ 任せてよいが、必ず検証                       │
│  ・レイアウト全体の設計                        │
│  ・レスポンシブの実装                          │
│  ・既存CSSの修正（副作用の確認が必須）          │
│  ・グラデーションや影の値                       │
├──────────────────────────────────────────────┤
│ ❌ 自分でやるべき                              │
│  ・「どんなデザインにするか」の決定             │
│  ・情報の優先順位づけ                          │
│  ・アクセシビリティの最終確認                   │
│  ・実機での見た目の確認                        │
└──────────────────────────────────────────────┘
```

### 特に注意：既存CSSの修正

```text
❌ 「このCSSを直して」（全文を貼る）
```

AIは**全体を書き直して返してきます**。すると、

- 何が変わったのかわからない
- 意図せず別の箇所が壊れる
- 学習にならない

```text
✅ 「以下のCSSで、カードの高さが揃いません。
     原因として考えられるものを3つ挙げ、それぞれの確認方法を教えてください。
     修正コードは出さないでください。」
```

**差分がわかる形で聞く**のが鉄則です。

## ✍️ 手を動かす⑤ ─ スクリーンショットを使う

多くのAIツールは画像を読めます。**デザインのスクリーンショットを渡す**と、精度が上がります。

```text
添付した画像は、私が作りたいWebページのデザイン案です。

このデザインを実装するにあたって、以下を教えてください。

1. HTMLの構造（どこを section / article / div にするか）
2. レイアウトに使うべき手法（Grid か Flexbox か、その理由）
3. 実装時に難しそうな箇所と、その対処方針
4. レスポンシブにするとき、どこをどう変えるべきか

コードはまだ書かないでください。設計方針だけ教えてください。
```

> 💡 **「コードはまだ書かないで」を付けるのが重要です。**
> いきなりコードを受け取ると、設計を考えるプロセスを飛ばしてしまいます。
> **設計 → 自分で実装 → レビュー**、の順が最も学習効果が高い流れです。

> ⚠️ 他社サイトのスクリーンショットをそのまま模写させて公開するのは、**著作権上の問題**になり得ます。学習目的の練習に留め、公開物は自分でデザインしてください。

## 🤖 AIに聞いてみよう

### ① 自分のCSS全体を診断させる

```text
以下は、私が第1部の学習で書いたCSSファイル全体です。
学習1ヶ月目の初学者が書いたものです。

（style.css を全部貼る）

次の観点でレビューしてください。

1. 現代のCSSとして不適切・古い書き方
2. 保守性の問題（命名、重複、詳細度）
3. レスポンシブ対応の抜け
4. アクセシビリティの問題
5. パフォーマンス上の懸念

各指摘について「なぜ問題か」「どういう考え方で直すべきか」を説明してください。
修正後のコードは書かないでください。私が自分で直します。

指摘は、影響の大きい順に並べてください。
```

> 💡 **これは第1部の総まとめとして、必ずやってください。** 自分では気づけない癖が見つかります。

### ② 出力を批判させる（セカンドオピニオン）

AIに書かせたCSSを、**新しい会話で**別途レビューさせます。

```text
以下のCSSをレビューしてください。Webの初学者が書いたコードです。

（AIが出力したCSSを貼る）

1. バグや意図しない挙動が起きる箇所
2. 現代のCSSとして推奨されない書き方
3. レスポンシブで壊れる可能性がある箇所
4. アクセシビリティの問題

厳しめに指摘してください。
```

> 💡 **「AIが書いた」と言わないのがコツです。** 「初学者が書いた」と伝えると、AIは遠慮なく指摘します。
> 自分の出力だと知っていると、庇う傾向があります。

## 🔧 やってみよう（演習）

**この演習は、AIを使うことが課題です。**

### 演習1（必須）

「手を動かす①」のプロンプトフレームワークを使って、**ABOUTセクションのCSS**をAIに書かせてください。

- [ ] 5つのブロック（何を / 構造 / 意図 / 具体指定 / 制約）で指示を書く
- [ ] 技術的な制約に、自分が学んだ手法を最低5つ書く
- [ ] 出力を、チェックリストで採点する
- [ ] 採点結果を `learning-log.md` に記録する
- [ ] 問題があった箇所を、**自分で修正する**

### 演習2（必須）─ AIの間違いを見つける

以下は、AIが出力したCSSの例です。**7つの問題**があります。すべて指摘してください。

```css
.card-container {
  display: flex;
  width: 1200px;
}

.card {
  float: left;
  width: 33.33%;
  padding: 20px;
  margin-right: 20px;
}

.card img {
  width: 300px;
  height: 200px;
}

.card a:focus {
  outline: none;
}

.card .title {
  font-size: 20px !important;
  -webkit-border-radius: 4px;
  -moz-border-radius: 4px;
  border-radius: 4px;
}

@media (max-width: 767px) {
  .card { width: 100%; }
}
```

<details>
<summary>答えを見る（自力でやってから開いてください）</summary>

1. **`width: 1200px` が固定** → それ未満の画面で横スクロールが出る。`max-width` にする
2. **`display: flex` と `float` の併用** → Flexコンテナの子では float は無効。**AIが古い手法を混ぜた典型例**
3. **`width: 33.33%` + `padding` + `margin-right`** → `box-sizing` の指定がなければ合計100%を超える。`flex: 1` か Grid の `fr` を使うべき
4. **`.card img` が固定サイズ** → レスポンシブで歪む。`width: 100%; aspect-ratio: 3/2; object-fit: cover;` にする
5. **`outline: none`** → キーボード操作でフォーカス位置がわからなくなる。**絶対にやってはいけない**。代替スタイルを用意すべき
6. **`!important`** → 詳細度の問題を力技で解決している。セレクタを見直すべき
7. **ベンダープレフィックス（`-webkit-` `-moz-` の border-radius）** → 10年以上前の対応。現代のブラウザには不要

（おまけ：`max-width` のメディアクエリ1つだけで、モバイルファーストになっていない）

</details>

### 演習3（挑戦）

**AIと交互に改善する**練習です。

1. カフェLPの好きなセクションを1つ選ぶ
2. AIに「もっと洗練させるための改善案を5つ、コードなしで」と聞く
3. その中から**自分が納得したものだけ**を選ぶ
4. **自分の手で**実装する
5. 実装後、AIにレビューさせる
6. 指摘を受けて、また自分で直す

**このループを2周してください。**

> 💡 これが実務でのAI活用の実態です。「AIに作らせる」のではなく「**AIと壁打ちしながら自分で作る**」。
> このループを回せることが、これからのエンジニアの基本スキルです。
