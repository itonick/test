## A. 学ぶとき

### A-1. 概念がわからない

```text
私はWeb開発の初学者です。「（用語）」がわかりません。

次の順番で説明してください。
1. 日常生活の比喩で、一言で言うと何か
2. なぜそれが必要なのか（それがない世界はどう困るのか）
3. 実際のコードでの最小の例
4. 初学者がよく誤解するポイント

専門用語を使う場合は、必ずその場で意味を添えてください。
```

### A-2. 2つの違いがわからない

```text
「（A）」と「（B）」の違いがわかりません。

1. それぞれを一言で
2. 決定的な違いは何か
3. どういう場面でどちらを使うのか、判断基準を表で
4. 初学者が間違えやすい典型例

を教えてください。
```

> 使いどころ：`div` と `span` / `let` と `const` / `==` と `===` / `GET` と `POST` / `include` と `require` など

### A-3. コードの意味がわからない

```text
以下のコードの意味がわかりません。

（コードを貼る）

1行ずつ、何をしているかコメントを付けて解説してください。
また、この処理を日本語の手順書として書き直すとどうなりますか？
```

### A-4. 「なぜこう書くのか」を掘る

```text
（コードや書き方を貼る）

この書き方について教えてください。
1. なぜこの書き方が必要なのですか？
2. これを書かないとどうなりますか？
3. 他の書き方はありますか？あるなら、それぞれの長所と短所は？
```

### A-5. 全体像を掴む

```text
これから「（技術名）」を学びます。

学び始める前に、全体像を把握したいです。
1. この技術は、何を解決するために生まれたのか
2. 主要な構成要素を5つ以内で
3. それらの関係を、簡単な図（テキストアート）で
4. 初学者が最初に理解すべき順番

を教えてください。
```

## B. 詰まったとき

### B-1. エラーが出た（基本テンプレート）

> ⚠️ **自分で15分読んでから使ってください。**

```text
【状況】
（何をしようとして、何が起きたか）

【環境】
- OS: （Windows 11 / macOS 14 など）
- 実行環境: （XAMPP 8.2 / MAMP / Laravel 11 など）
- ブラウザ: Chrome

【エラーメッセージ】
（省略せず、丸ごとコピペ）

【該当コード】
（ファイル全体を貼る）

【自分で試したこと】
-
-

【お願い】
1. 原因として考えられるものを、可能性の高い順に3つ挙げてください
2. それぞれについて、原因かどうかを確認する手順を教えてください
3. すぐに修正コードを出すのではなく、まず私が自分で確認できる手順を示してください
```

### B-2. エラーは出ないが、思った通りに動かない

```text
エラーは出ませんが、期待した動作になりません。

【期待する動作】

【実際の動作】

【コード】
（貼る）

原因を切り分けるための確認手順を、上から順に教えてください。
どこにログ（var_dump / console.log）を仕込めば原因がわかるかも教えてください。
```

### B-3. 画面が真っ白になった（PHP）

```text
PHPのページにアクセスすると、画面が真っ白で何も表示されません。
エラーメッセージも出ません。

環境: （XAMPP 8.2 / Windows 11 など）

1. 白画面になる原因として考えられるものを挙げてください
2. エラーメッセージを画面に表示させる設定方法を教えてください
3. エラーログの場所と、その見方を教えてください
```

### B-4. CSSが効かない

```text
以下のCSSを書きましたが、見た目が変わりません。

【HTML】
（貼る）

【CSS】
（貼る）

CSSが効かない原因のチェックリストを、確認すべき順に出してください。
また、Chrome の開発者ツールを使って原因を特定する手順も教えてください。
```

### B-5. 環境構築で詰まった

```text
（XAMPP / MAMP / Composer / Laravel）のインストール中に、以下の問題が起きています。

【やろうとしたこと】
【出たエラー・メッセージ】
（丸ごと貼る）
【OSとバージョン】

考えられる原因を可能性の高い順に3つ、それぞれの確認手順と対処法を、
コマンドや画面操作のレベルまで具体的に教えてください。
```

## C. 書いたコードを良くするとき

### C-1. コードレビュー（学習用）

```text
以下は、私が書いた（言語名）のコードです。学習（N）週目の初学者が書いたものです。

（コードを貼る）

次の観点でレビューしてください。
1. 動作上のバグ
2. セキュリティ上の問題（あれば、なぜ危険かも）
3. 読みやすさ・命名
4. もっと簡潔に書ける箇所

ただし、修正後のコードは提示しないでください。
「どこを・なぜ直すべきか」だけを指摘してください。私が自分で直します。
```

### C-2. セキュリティレビュー

> 💡 **新しい会話で**聞いてください。

```text
以下のコードを、セキュリティの観点からレビューしてください。
Webアプリケーションで、一般ユーザーからの入力を扱うコードです。

（コードを貼る）

次の観点で、問題があれば具体的に指摘してください。
- SQLインジェクション
- XSS（クロスサイトスクリプティング）
- CSRF
- ファイルアップロードの脆弱性
- 認証・認可の不備
- 機密情報のハードコーディング

それぞれ、なぜ危険か・攻撃されると何が起きるかも説明してください。
問題がない場合は「問題なし」と明言してください。
```

### C-3. リファクタリング

```text
以下のコードは動いていますが、自分でも読みにくいと感じています。

（コードを貼る）

1. 読みにくくなっている原因を指摘してください
2. どういう方針で整理すべきか、考え方を教えてください
3. 変更後のコードは書かず、方針だけ示してください
```

### C-4. 命名に迷った

```text
（何をする変数 / 関数 / クラスか、を説明）

この（変数 / 関数）の名前を10個提案してください。
それぞれについて、なぜその名前がよいか / 避けたほうがよいかを一言添えてください。
（言語名）の一般的な命名規則に従ってください。
```

### C-5. テストの観点を出す

```text
以下の機能を実装しました。

（機能の説明とコードを貼る）

この機能をテストするとき、確認すべきケースを網羅的に挙げてください。
- 正常系
- 異常系（空・想定外の型・極端な値・特殊文字・日本語）
- 境界値

チェックリスト形式でお願いします。
```

## D. 設計を考えるとき

### D-1. テーブル設計の相談

```text
（アプリの説明）を作ります。

【必要な機能】
-
-

このアプリに必要なテーブル構成を提案してください。
1. テーブル一覧と、それぞれの役割
2. 各テーブルのカラム（型・制約つき）
3. テーブル間のリレーション
4. この設計で困りそうな点、将来の拡張で問題になりそうな点

MySQL 8.0 / Laravel 11 を想定しています。
```

### D-2. 実装方針の相談

```text
（実現したい機能）を実装したいです。

【現在の技術構成】
【自分が考えた方法】
（あれば書く）

1. 実装方法の選択肢を2〜3つ挙げてください
2. それぞれのメリット・デメリットを表で
3. 初学者が実装する前提で、どれを推奨しますか？その理由は？
4. 実装の大まかなステップ

コードはまだ書かないでください。方針だけ知りたいです。
```

### D-3. 要件を整理する

```text
（作りたいものをざっくり説明）

これを作るための要件を整理したいです。
1. 必須機能（MVP）と、あとで足せる機能に分類してください
2. 各機能について、必要な画面を挙げてください
3. 初学者が2週間で作るとしたら、どこまでに絞るべきですか？

作りすぎて完成しないパターンを避けたいです。
```

## E. 自分をテストするとき

### E-1. クイズを作らせる

```text
私は「（学習した内容）」を学びました。

理解度を確認するため、初学者向けのクイズを5問出してください。
- 易しい順に
- 「知識を問う」だけでなく「使えるか」を問う問題を混ぜて
- まだ答えは書かないでください

私が回答したら、1問ずつ採点し、間違いは「なぜ間違えたか」の
思考のズレを指摘してください。
```

### E-2. 演習問題を作らせる

```text
「（学習した内容）」の練習問題を5問作ってください。

条件:
- 実務でありそうな題材（商品リスト、ユーザー一覧など）
- 各問題に「入力データ」と「期待する出力」を明記
- 難易度を段階的に
- 解答はまだ出さないでください
```

### E-3. 説明させて理解を確認する（ラバーダック）

```text
これから私が「（学習した内容）」を自分の言葉で説明します。
あなたは、初学者に教える立場のエンジニアとして、
私の説明に間違いや説明不足がないかチェックしてください。

【私の説明】
（自分の言葉で書く）

1. 正しく理解できている点
2. 間違っている点
3. 説明が足りていない点
4. 私がまだ気づいていない、次に学ぶべきこと
```

> 💡 **これが最強の理解度チェックです。** 説明できないことは、理解していません。

## F. AIを検証するとき

### F-1. 質問の理解を確認させる

```text
回答する前に、私の質問をあなたがどう理解したかを1〜2文で要約してください。
それが合っていれば、私が「OK」と言うので、そのあと回答してください。
```

### F-2. 情報の鮮度を確認する

```text
いま教えていただいた方法について確認させてください。

1. この書き方は、（技術名 バージョン）で現在も推奨されていますか？
2. 非推奨・廃止予定になっていませんか？
3. 公式ドキュメントの該当ページのURLを教えてください
4. あなたの回答のうち、確信が持てない部分があれば明示してください
```

### F-3. 別解を出させる（一択を疑う）

```text
いま提示していただいた方法以外に、同じことを実現する方法はありますか？

- 少なくとも2つの別解
- それぞれのメリット・デメリット
- 初学者にとって、どれが最も理解しやすいか

を教えてください。
```

### F-4. 反対意見を言わせる

```text
いまの提案について、あえて批判的な立場から意見を述べてください。

- この方法の弱点
- この方法を選ぶべきでないケース
- 経験豊富なエンジニアなら指摘しそうなこと
```

## G. 就職・ポートフォリオ

### G-1. READMEを改善する

```text
以下は、私のポートフォリオのREADMEです。

（貼る）

採用担当者やエンジニアが読むことを想定して、改善点を指摘してください。
- 足りていない情報
- 伝わりにくい表現
- 技術力が伝わる書き方になっているか

書き直したREADMEは提示せず、指摘だけお願いします。
```

### G-2. ポートフォリオの弱点を洗い出す

```text
以下のポートフォリオ作品について、
未経験からのエンジニア転職を目指す立場で評価してください。

【アプリの概要】
【使用技術】
【実装した機能】

1. 評価されそうな点
2. 弱いと見られそうな点
3. あと1つ機能を足すなら何がよいか、理由つきで3案
4. 面接で聞かれそうな技術的な質問を5つ
```

## 使ってはいけないプロンプト

以下は、学習を殺します。**使わないでください。**

| ❌ ダメなプロンプト | なぜダメか | 代わりに |
| --- | --- | --- |
| 「ToDoアプリを作って」 | 何も身につかない。3日後に自分で作れない | 自分で書き、レビューさせる（C-1） |
| 「このエラー直して」 | エラーが読めるようにならない | 原因候補を挙げさせる（B-1） |
| 「この課題の答えを教えて」 | 演習の意味が消える | ヒントだけ求める |
| 「全部書き直して」 | 差分がわからず、何が問題だったか残らない | 指摘だけさせる（C-3） |

### ヒントだけもらうプロンプト

答えが欲しくなったら、代わりにこれを使ってください。

```text
以下の課題に取り組んでいますが、詰まっています。

【課題】
【現在の自分のコード】
【どこまではわかっているか】
【どこがわからないか】

答えは教えないでください。
私が自力で解けるように、次の一歩のヒントだけをください。
それでも解けなかったら、もう一段階だけヒントをください。
```

## プロンプトを自分用に育てる

上のテンプレートは出発点です。使いながら、自分に合うよう書き換えてください。

**育てるコツ**

1. 良い回答が返ってきたプロンプトは、`my-prompts.md` に保存する
2. 回答がイマイチだったら、**プロンプトのどこが曖昧だったか**を考える
3. 「〜してください」を「〜しないでください」に変えると効くことが多い
4. 出力形式（表で / 3つ / 箇条書きで / コードなしで）を指定すると安定する

> 💡 プロンプトを書く力は、**仕様を言語化する力**そのものです。これは、そのままエンジニアの実務能力になります。
