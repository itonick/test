# 6-4 オリジナルアプリを企画する

> 🎯 **このレッスンのゴール**
> - 「作りたいもの」を、完成させられる企画に落とし込める
> - ポートフォリオとして評価されるアプリのテーマの選び方が分かる
> - 自分の企画書を1本書き上げる

所要 120分 / 難度 🟡 ／ 🏁 成果物：企画書

---

## 📖 「何を作るか」で、ポートフォリオの価値が決まる

フリマアプリ（第5部）は、技術を学ぶための課題でした。次は**あなた自身の作品**を作ります。
ここで多くの人が「何を作ればいいか分からない」で止まります。このレッスンで抜け出します。

ポートフォリオ作品に求められるのは、実は「すごい技術」ではありません。

- ✅ **ちゃんと動く**（バグだらけでない）
- ✅ **作った理由が語れる**（なぜこれを作ったか）
- ✅ **基本が押さえられている**（CRUD・認証・認可・DB設計・テスト）

逆に、**独自性を狙いすぎて完成しない**のが一番もったいない。まずは「完成させる」が最優先です。

---

## 📖 テーマの選び方：3つの軸

### 軸1：自分の「困りごと」から選ぶ（おすすめ）

あなたが実際に困っていることは、作るモチベーションが続き、面接でも語れます。

- 読んだ本を記録・管理したい → 読書記録アプリ
- 家計を管理したい → 家計簿アプリ
- 筋トレの記録を残したい → トレーニング記録アプリ
- 趣味の作品を投稿・共有したい → 作品投稿アプリ

### 軸2：身近な誰かの困りごとから選ぶ

家族・友人・バイト先の「あったら便利」も良いテーマ。「誰のために作ったか」が語れます。

### 軸3：定番アプリを自分なりにアレンジ

ゼロから奇抜なものを狙うより、**定番＋小さな独自性**が完成しやすい。

- ブログ + タグ・下書き機能
- ToDo + チーム共有
- レビューサイト + ランキング

> 🧠 **「作りたい」より「作り切れる」を優先**。
> 壮大なSNSやマッチングアプリは、初学者が一人で完成させるには重すぎます。
> フリマアプリと同じくらいの規模（テーブル2〜4個、CRUD＋認証＋認可）が現実的です。

---

## 📖 避けたほうがいいテーマ

| テーマ | なぜ難しいか |
| --- | --- |
| リアルタイムチャット | WebSocket など、この教材の範囲外の技術が必要 |
| 決済のある本格ECサイト | 実際の決済連携・セキュリティ責任が重い |
| 大規模SNS | 機能が多すぎて完成しない |
| AI/機械学習が主役 | 別領域の学習が大量に必要 |
| 位置情報・地図が主役 | 外部API依存が大きく、ハマると抜けられない |

> 💡 これらを「入れてはいけない」のではなく、**MVPの主役にしない**ということ。
> まず基本機能で完成させ、余裕があれば Should/Could として足すのが安全です。

---

## ✍️ 手を動かす① ─ アイデアを3つ出して1つ選ぶ

いきなり1つに絞らず、3案出して比較します。

各案について、次を1行ずつ書く：

```
案A：読書記録アプリ
  - 誰のため：本をよく読む自分
  - 主な機能：本の登録/一覧/検索、読了記録、感想メモ
  - 使う技術：CRUD, 認証, 画像(表紙), 検索
  - 完成できそう度：★★★（テーブル2つで足りる）

案B：...
案C：...
```

そして、**「完成できそう度」が高く、語れる理由があるもの**を選びます。
凝った案より、確実に完成する案を。

> 🆘 **ここで詰まったら**（作りたいテーマが思いつかない）
> - **探し方**：「自分／身近な人の**困りごと**」から探すと、作る動機が続き、面接でも語れます（記録・管理・共有系は作りやすい）。ゼロから奇抜を狙わず、**定番＋小さな独自性**が完成しやすい
> - **AIをブレスト相手に使う**（テーマを**決めるのは自分**）：
>   「Laravelを学んだ初学者です。CRUD・認証・認可を活かせる、2週間で作れるポートフォリオ用アプリのアイデアを、身近な困りごとベースで5つ提案してください。各案の完成難易度も添えてください」
> - AIが出した案は**あくまで種**。自分が「作りたい・語れる」と思えるものだけ選んでください。丸投げで決めた題材は、途中で手が止まります。

---

## ✍️ 手を動かす② ─ 企画書を書く

選んだ案を、企画書（`docs/planning.md`）にまとめます。

```markdown
# ○○アプリ 企画書

## 1. 作るもの（1文で）
（例：読んだ本を記録し、感想を残せる個人用の読書記録アプリ）

## 2. なぜ作るか / 誰のためか
（自分や身近な人の、どんな困りごとを解決するか。面接で語る核）

## 3. コアとなる体験（このアプリの「主役」機能）
（例：本を登録して「読了」にすると、読書履歴が積み上がっていく）

## 4. 主な機能（MoSCoW）
- Must:
- Should:
- Could:
- Won't（今回やらない）:

## 5. 使用技術
（Laravel, MySQL, Blade など。フリマアプリで使ったものが基本）

## 6. この教材で学んだ、どの技術を使うか
（認証=5-10 / 認可=5-11 / 画像=5-12 / 検索=5-13 / テスト=5-14 など）

## 7. 完成の定義（MVP）
（「これができたら第一段階完成」を明記）
```

> 🧠 **項目6が重要**。「学んだことを使い切る」意識で企画すると、
> ポートフォリオが「教材をこなした証明」になり、実力が伝わります。

---

## ✍️ 手を動かす③ ─ 企画をレビューする（自問リスト）

書いた企画を、着手前に自分でチェックします。

- [ ] MVPは、フリマアプリと同程度の規模に収まっているか（重すぎないか）
- [ ] テーブルは2〜4個くらいか（多すぎないか）
- [ ] 「なぜ作るか」を、自分の言葉で30秒語れるか
- [ ] 認証・認可・DB設計・CRUDという基本が含まれているか
- [ ] Won't を決めて、スコープに線を引けているか
- [ ] この教材で学んだ技術で作り切れるか（範囲外の技術が主役になっていないか）

1つでも不安があれば、企画を**小さく削る**方向で調整します。

---

## 🤖 AIに聞いてみよう

企画も、AIとの壁打ちが有効です。ただし**決めるのは自分**。

### 使えるプロンプト例

```
Laravel の学習を終えた初学者です。ポートフォリオ用のWebアプリをMVPで作りたい。
次の3案について、「初学者が2週間で完成できるか」「基本技術（CRUD/認証/認可/DB設計）を
学んだ成果を見せられるか」の観点で評価し、改善案をください。
- 案A: 読書記録アプリ
- 案B: 家計簿アプリ
- 案C: 趣味の作品投稿アプリ
また、それぞれで「今回やらない方がいい機能」も教えてください。
```

### 🔍 AIの答えを疑うチェックリスト

- [ ] 提案されたスコープが**完成可能な量**か（AIは機能を盛りがち）
- [ ] 「やらない方がいい機能」をちゃんと示しているか
- [ ] あなたが**本当に作りたい／語れる**テーマになっているか（AIに決めさせない）
- [ ] 範囲外の技術（リアルタイム・決済・AI）を主役に据えていないか
- [ ] 基本技術の学習成果が見える構成か

> ⚠️ **企画をAIに丸投げしない**。AIが出したテーマは、あなたのモチベーションと結びつかず、
> 「なぜ作ったか」を語れません。AIは**壁打ち相手**であって、企画者はあなたです。

---

## 🔧 やってみよう（演習）

1. アイデアを3案出し、各案を「誰のため / 機能 / 技術 / 完成できそう度」で比較
2. 1つ選び、企画書（`docs/planning.md`）を書く
3. 「なぜ作るか」を声に出して30秒で説明する練習をする
4. 自問リストで企画をレビューし、重ければ削る
5. 6-3の要件定義（機能・画面・ER図）を、この企画に対して作る
6. GitHubにリポジトリを作り、企画書と要件定義書を push
