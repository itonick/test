# 6-1 Git / GitHub の基本操作

> 🎯 **このレッスンのゴール**
> - Git で作業を記録し、GitHub に公開できる
> - `add` → `commit` → `push` の流れを、意味とともに使える
> - 作ったフリマアプリを GitHub に上げて、URLで人に見せられる

所要 150分 / 難度 🟡 ／ 🏁 成果物：GitHubリポジトリ

---

## 📖 Git は「作業のセーブポイント」、GitHub は「公開の場」

- **Git** … あなたのPC上で、コードの変更履歴を記録するツール
- **GitHub** … その履歴をネット上に置いて、公開・共有できるサービス

ゲームのセーブに例えると：

| | 役割 |
| --- | --- |
| `commit` | セーブする（この時点に戻れる） |
| `push` | セーブデータをクラウドにアップロード |
| GitHub | クラウドのセーブ置き場（他人にも見せられる） |

> 💡 **なぜ必要？**
> 「昨日は動いていたのに、いじったら動かなくなった」を、Gitは**巻き戻し**で救います。
> そして就職・案件では「GitHubのURL」が名刺代わり。避けて通れません。

> 📌 このレッスンは第1部が終わった時点で先に済ませておくと、以降の学習が楽になります。

## ✍️ 手を動かす① ─ Git を準備する

インストールは第0部の環境構築で済んでいる前提です。最初の1回だけ、名前とメールを登録します。

```bash
git config --global user.name "あなたの名前"
git config --global user.email "you@example.com"

# 設定を確認
git config --global --list
```

> 💡 ここのメールは、GitHubに登録するメールと合わせておくと、コミットがあなたの実績として記録されます。

---

## ✍️ 手を動かす② ─ リポジトリを作って最初のコミット

フリマアプリのフォルダで実行します。

```bash
cd flea-market            # 自分のプロジェクトフォルダへ

git init                  # このフォルダをGit管理下に（1回だけ）

git status                # 今どうなっているか（迷ったら常にこれ）
```

`git status` は**いちばん使うコマンド**。困ったらまず打つ。今の状態を教えてくれます。

### `.gitignore` で「上げてはいけないもの」を除外

Laravelプロジェクトなら、次を上げてはいけません（Laravelのひな形には最初から入っています）。

```gitignore
/vendor
/node_modules
.env            # ← パスワードやAPIキー。絶対に公開しない
/storage/*.key
```

> 🔒 **`.env` を push したら事故**
> DBパスワードやAPIキーが書かれた `.env` は、GitHubに上げてはいけません。
> 一度上げると、消してもネットに残る可能性があります（第4部・機密の扱いの延長）。
> `.gitignore` に入っているか、`push` 前に必ず確認。

### コミットする

```bash
git add .                 # 変更を「次のコミットに含める」候補に（ステージング）
git commit -m "フリマアプリの初期状態"   # セーブ（-m はメッセージ）
```

`add` → `commit` の2段階なのがポイント。「どれをセーブに含めるか選んでから、セーブする」。

## ✍️ 手を動かす③ ─ コミットを積み重ねる（普段の流れ）

機能を1つ作ったら、こまめにコミットします。

```bash
# 何か作業する（例：商品検索を実装）

git status                          # 何が変わったか確認
git add .                           # 変更をステージング
git commit -m "商品検索機能を追加"    # コミット

git log --oneline                   # これまでのコミット一覧
```

`git log --oneline` の出力例：

```
a1b2c3d 商品検索機能を追加
e4f5g6h 購入機能を実装
i7j8k9l フリマアプリの初期状態
```

### 良いコミットメッセージ

| ❌ 悪い | ✅ 良い |
| --- | --- |
| `update` | `商品検索機能を追加` |
| `修正` | `購入時の二重販売バグを修正` |
| `aaa` | `README にセットアップ手順を追記` |

> 💡 **「何をしたか」を後から読んで分かる**ように。未来の自分（と採用担当）が読みます。
> 1コミット＝1つのまとまった変更、を心がけると履歴がきれいになります。

## ✍️ 手を動かす④ ─ GitHub に公開する

1. [GitHub](https://github.com) でアカウントを作る（無料）
2. 右上「＋」→「New repository」
3. リポジトリ名（例 `flea-market`）を入れ、**Public**（公開）を選ぶ
4. 「README や .gitignore は追加しない」（手元にあるので）→ Create

作成後に表示されるコマンドのうち、「既存のリポジトリを push」を使います。

```bash
git remote add origin https://github.com/あなたの名前/flea-market.git
git branch -M main
git push -u origin main
```

これで GitHub にコードが上がりました。ブラウザでリポジトリを開くと、コードが見えます。
この**URLが、あなたのポートフォリオのリンク**になります。

### 2回目以降の公開

```bash
git add .
git commit -m "変更の内容"
git push                 # 2回目以降は push だけでOK
```

## ✍️ 手を動かす⑤ ─ 巻き戻し・確認の基本

```bash
# 直前のコミットとの差分を見る
git diff

# 特定ファイルの変更を「コミット前なら」取り消す
git restore ファイル名

# コミット履歴を見る
git log --oneline
```

> 🧠 まずは「`status` で確認 → `add` → `commit` → `push`」の1本道を体に入れましょう。
> ブランチやマージなどの応用は、この基本が手に馴染んでからで十分です。

## ⚠️ つまずきポイントまとめ

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `.env` を push してしまった | `.gitignore` を確認していなかった | すぐにパスワード/キーを変更。履歴からの完全削除は要注意作業 |
| push で認証エラー | パスワード認証は廃止 | Personal Access Token または SSH 鍵を設定 |
| `vendor` を大量に push | `.gitignore` が効いていない | `.gitignore` に `/vendor` があるか確認 |
| commit できない | `user.name`/`user.email` 未設定 | `git config --global` で設定 |
| どのファイルが変わったか分からない | 確認していない | まず `git status` |

> 🔑 **GitHubの認証**：いまはパスワードではなく **Personal Access Token（PAT）** か
> **SSH鍵**を使います。GitHubの「Settings → Developer settings」から作れます。
> 手順はGitHub公式が最新なので、そちらを見ながら設定してください。

## 🤖 AIに聞いてみよう

Gitはエラーメッセージが独特で、初学者がパニックになりがち。AIが強い味方になります。

### 使えるプロンプト例

```
git push したらこのエラーが出ました。意味と対処を、初心者にも分かるように教えてください。
（エラーメッセージを貼る）
```

```
間違って .env を git add してしまいました。コミット前です。
安全に取り消す手順を教えてください。
```

### 🔍 AIの答えを疑うチェックリスト

- [ ] 提案コマンドが**破壊的**でないか？（`git reset --hard` や `push --force` は履歴を壊すことがある）
- [ ] 「なぜそうなるか」の説明があるか（意味を理解してから実行する）
- [ ] `.env` など**機密**を GitHub に残したままにする手順になっていないか
- [ ] 自分の状況（コミット前？後？push済み？）に合った手順か

> ⚠️ **`git` のAI提案は、実行前に一呼吸**。特に `--force` や `reset --hard` は、
> 意味が分からないまま実行すると作業が消えます。分からなければ、まず `git status` の
> 結果ごとAIに見せて相談してください。

## 🔧 やってみよう（演習）

1. `git config` で名前とメールを設定
2. フリマアプリで `git init` → `.gitignore` に `.env` があることを確認
3. 最初のコミットを作る
4. 機能ごとに3回以上、意味のあるメッセージでコミットする
5. GitHub にリポジトリを作り、`push` して公開
6. ブラウザでリポジトリを開き、コードと履歴が見えることを確認
7. わざとファイルを1つ変更 → `git diff` で差分を確認 → `git restore` で戻す
