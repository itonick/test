# 6-6 レンタルサーバーにデプロイする

> 🎯 **このレッスンのゴール**
> - 手元で動くアプリを、インターネットに公開できる
> - デプロイで詰まる「本番特有のポイント」を理解する
> - ポートフォリオに「動くURL」を載せる

所要 180分 / 難度 🔴 ／ 🏁 成果物：公開URL

---

## 📖 デプロイ＝「自分のPCの外」で動かす

これまでアプリは `php artisan serve` で**自分のPCの中**だけで動いていました。
**デプロイ**とは、それをサーバーに置いて、**世界中の誰でもURLで見られる**状態にすることです。

> 🧠 なぜやるか：READMEに「動くデモURL」があると、採用担当がその場で触れます。
> 「動いている証拠」ほど強いアピールはありません。コードを読ませる前に、体験してもらえる。

---

## 📖 どこに公開するか（初学者向けの選択肢）

| 選択肢 | 特徴 | 難度 |
| --- | --- | --- |
| **レンタルサーバー**（例: エックスサーバー等） | 日本語情報が多い、PHP/MySQL標準対応、有料 | 🟡 |
| **PaaS**（例: Render, Railway 等） | Gitと連携して自動デプロイ、無料枠あり | 🟡 |
| **VPS/クラウド**（例: さくらVPS, AWS等） | 自由度最大、サーバー構築を全部自分で | 🔴 |

この教材では、**Laravelを動かせるレンタルサーバー or PaaS** を想定して、
「どの環境でも共通で押さえるべき勘所」を解説します。
（各サービスの画面手順は頻繁に変わるので、**公式ドキュメントを最新の正**とし、
ここでは「何をやっているか」の理解に集中します。）

> 💡 まず1つ確実に公開することが目的。凝った構成は後からで十分です。

## 📖 デプロイの全体像（Laravelの場合）

手元と本番の違いを埋める作業、と考えると分かりやすいです。

```
1. サーバーにコードを置く（git clone / アップロード）
2. composer install（本番用に依存を入れる）
3. .env を本番用に作る（DB接続・APP_KEY・APP_ENV=production）
4. php artisan key:generate（未設定なら）
5. php artisan migrate（本番DBにテーブルを作る）
6. 公開ディレクトリを public/ に向ける（重要）
7. npm run build（CSS/JSをビルドした成果物を置く）
8. storage:link（画像を使うなら）
9. 権限設定（storage / bootstrap/cache を書き込み可に）
```

---

## ✍️ 手を動かす① ─ 本番用 `.env` を用意する

手元の `.env` を**そのまま使ってはいけません**。本番用に作り直します。

```env
APP_NAME="読書記録アプリ"
APP_ENV=production          # ← 本番。development のままにしない
APP_DEBUG=false             # ← 本番では必ず false（後述）
APP_KEY=base64:...          # key:generate で生成
APP_URL=https://あなたのドメイン

DB_CONNECTION=mysql
DB_HOST=（サーバーのDBホスト）
DB_DATABASE=（本番DB名）
DB_USERNAME=（本番DBユーザー）
DB_PASSWORD=（本番DBパスワード）
```

> 🔒 **`APP_DEBUG=false` は最重要のセキュリティ設定**
> `true` のままだと、エラー画面に**DBの接続情報やコードの中身が丸見え**になります。
> 攻撃者に手がかりを与える大穴。本番は必ず `false`。第4部で学んだ「機密を守る」の実践です。

> 🔒 `.env` はサーバー上に置きますが、**GitHubには push しない**（6-1）。
> `.env.example`（値を空にしたテンプレート）だけをリポジトリに入れ、本番の実値はサーバーで設定します。

---

## ✍️ 手を動かす② ─ 公開ディレクトリを `public/` に向ける

ここが**Laravelデプロイ最大のハマりどころ**です。

Laravelプロジェクトのうち、**外部に見せていいのは `public/` の中だけ**。
`app/` や `.env` が置いてあるプロジェクトルートを公開してしまうと、
**ソースコードや `.env` がURLで見えてしまう**大事故になります。

- ✅ 正しい：ブラウザからのアクセスは `public/index.php` に届く
- ❌ 危険：プロジェクトルートが公開され、`.env` に直接アクセスできてしまう

やり方はサーバーによります：

- レンタルサーバー：公開フォルダ（`public_html` 等）の向き先を `public/` に設定、
  またはシンボリックリンクを張る
- PaaS：ドキュメントルートを `public` に指定する設定を書く

> ⚠️ デプロイ後、`https://あなたのドメイン/.env` にアクセスしてみて、
> **中身が表示されないこと**を必ず確認。表示されたら、公開ディレクトリの設定ミスです（緊急）。

---

## ✍️ 手を動かす③ ─ 本番向けの最適化

本番では、設定やルートを**キャッシュ**して高速化します。

```bash
composer install --optimize-autoloader --no-dev   # 開発用パッケージを入れない
php artisan config:cache      # 設定をキャッシュ
php artisan route:cache       # ルートをキャッシュ
php artisan view:cache        # ビューをキャッシュ
```

> 💡 `config:cache` を使ったら、以降 `.env` を変えても即座には反映されません。
> `.env` を変えたら `php artisan config:cache` をやり直す、と覚えておきましょう。

---

## ✍️ 手を動かす④ ─ 権限とストレージ

Laravelは `storage/` と `bootstrap/cache/` に書き込みます。ここが書き込み不可だと動きません。

```bash
# サーバー上で（環境により異なる。公式手順を確認）
chmod -R 775 storage bootstrap/cache

php artisan storage:link      # 画像アップロードを使うなら（5-12）
```

> ⚠️ **画像が表示されない**の本番あるある：`storage:link` 忘れ、または権限不足。
> 手元（5-12）と同じ罠が、本番でも待っています。

---

## ✍️ 手を動かす⑤ ─ 公開後のチェック

デプロイできたら、本番URLで一通り確認します。

- [ ] トップページが表示される
- [ ] 新規登録・ログインできる
- [ ] 主要機能（CRUD）が動く
- [ ] 画像がアップロード・表示できる
- [ ] `https://ドメイン/.env` が**見えない**（最重要）
- [ ] エラー時に**詳細が出ない**（`APP_DEBUG=false` の確認）
- [ ] `https://`（SSL）で見えている（`http://` のままにしない）

---

## ⚠️ つまずきポイントまとめ

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 500 エラーで真っ白 | `APP_KEY`未設定 / 権限 / `.env`不備 | `key:generate`、`storage`権限、ログ確認 |
| `.env` が見える | 公開ディレクトリがルートを向いている | 公開先を `public/` に |
| エラーに機密が丸見え | `APP_DEBUG=true` | `false` にして `config:cache` |
| CSSが効かない | `npm run build` していない | ビルド成果物を配置 |
| 画像が出ない | `storage:link` 忘れ / 権限 | リンクを張る、権限確認 |
| DBエラー | 本番DB情報が違う | `.env` のDB設定を確認、`migrate`済みか |
| `.env` 変更が効かない | `config:cache` 済み | `config:cache` をやり直す |

> 🧠 **本番で詰まったら、まずログを見る**：`storage/logs/laravel.log`。
> `APP_DEBUG=false` で画面にエラーが出ない分、ログが頼りです。

## 🤖 AIに聞いてみよう

デプロイはサーバーごとに事情が違い、AIの一般論が外れることもあります。**公式手順と併用**を。

### 使えるプロンプト例

```
Laravel 11 のアプリを ○○（サーバー名）にデプロイしたら、500エラーになりました。
storage/logs/laravel.log にはこう出ています：
（ログを貼る）
考えられる原因と、確認する順番を教えてください。
```

### 🔍 AIの答えを疑うチェックリスト

- [ ] `APP_DEBUG=false` を**外させようと**していないか（デバッグのため一時的に、でも戻すこと）
- [ ] `.env` を GitHub に push する手順になっていないか（**絶対NG**）
- [ ] 公開ディレクトリを `public/` に向ける話に触れているか
- [ ] あなたのサーバー（レンタル/PaaS/VPS）に合った手順か（環境を伝える）
- [ ] 権限を `777`（誰でも書き込み可）にしろと言っていないか（緩すぎ。`775`程度に）

> ⚠️ デバッグのため一時的に `APP_DEBUG=true` にすることはありますが、
> **原因が分かったら必ず `false` に戻す**。戻し忘れが情報漏洩の典型です。

## 🔧 やってみよう（演習）

1. デプロイ先を1つ選ぶ（レンタルサーバー or PaaSの無料枠）
2. 本番用 `.env` を作る（`APP_ENV=production` / `APP_DEBUG=false`）
3. コードを配置し、`composer install` → `migrate` → ビルド
4. 公開ディレクトリを `public/` に向ける
5. `storage:link` と権限を設定
6. 公開URLで「公開後のチェック」を全項目確認
7. **`/.env` が見えないこと**を必ず確認
8. READMEの先頭に「🔗 デモ: https://...」を追記して push
