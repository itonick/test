# 2-12 AIとペアプロする実践フロー

> 🎯 **このレッスンのゴール**
> - AIに「コードを書かせる」ことを解禁し、正しい手順で使う
> - 設計→実装→レビューのループを回せる
> - AIが書いたJavaScriptの危険な箇所を指摘できる

所要 120分 / 難度 🟡

---

## 📖 ここで「代筆者」を解禁します

第0部で、AIの5つ目の役割「**代筆者（コードを書かせる）**」を封印しました。

**いま解禁します。** 理由は、あなたが**採点できるようになった**からです。

第2部を終えた時点で、あなたは以下を知っています。

- `defer` がないと要素が取れない
- `innerHTML` にユーザー入力を渡すと XSS
- `addEventListener` に `()` を付けると即実行
- 後から追加した要素にはイベント委譲が必要
- `fetch` は404で reject しない
- `localStorage` は文字列しか保存できない
- 参照渡しで元データが壊れる

**これらは、AIが実際にやらかすミスの一覧でもあります。**

---

## 📖 AIが書くJavaScriptの典型的な問題

| 問題 | 具体例 | あなたが指摘できるか |
| --- | --- | --- |
| **XSS** | `el.innerHTML = userInput` | ✅ 2-6 |
| **エラー処理なし** | `fetch` の `res.ok` を確認しない | ✅ 2-10 |
| **状態の3つを忘れる** | loading / empty / error がない | ✅ 2-10 |
| **イベント委譲を使わない** | 再描画でリスナーが消える | ✅ 2-7 |
| **`var` を使う** | 古い学習データの影響 | ✅ 2-1 |
| **`==` を使う** | 同上 | ✅ 2-1 |
| **参照渡しの事故** | `push` で元配列を壊す | ✅ 2-4 |
| **アクセシビリティ無視** | `<div onclick>`、`outline: none` | ✅ 1-13, 2-7 |
| **`try...catch` で握りつぶす** | エラーを `console.log` だけして続行 | ✅ 2-9 |
| **localStorage を try で囲まない** | シークレットモードで落ちる | ✅ 2-11 |

> 💡 **このチェックリストを手元に置いてください。** AIの出力を採点する物差しになります。

## ✍️ 手を動かす① ─ 4ステップのループ

```
① 設計を相談する（コードを書かせない）
      ↓
② 自分で骨組みを書く
      ↓
③ 詰まった部分だけAIに書かせる
      ↓
④ レビューさせる → 自分で直す
      ↓
   （②に戻る）
```

**重要なのは、①と②を飛ばさないことです。**

いきなり③から始めると、「動くけど自分では書けないコード」が手元に残ります。

## ✍️ 手を動かす② ─ ステップ1：設計を相談する

```text
【作りたいもの】
ブラウザで動くToDoアプリを作ります。フレームワークは使わず、
素の HTML / CSS / JavaScript のみです。

【機能】
- タスクの追加、完了の切り替え、削除、編集
- 「すべて / 未完了 / 完了」の絞り込み
- localStorage への保存と復元
- 完了したタスクをまとめて削除

【私の技術レベル】
JavaScript を学習して1ヶ月。DOM操作、イベント委譲、
配列メソッド、localStorage は学習済み。

【聞きたいこと】
1. どんなデータ構造にすべきですか（1タスクが持つべき情報）
2. 状態（state）として何を管理すべきですか
3. 関数をどう分割すべきですか（役割の一覧だけ）
4. 実装の順番はどうすべきですか
5. この規模で気をつけるべき落とし穴を3つ

**コードはまだ1行も書かないでください。** 設計方針だけ教えてください。
```

### 期待される回答の例

AIは、こういう構造を提案してくるはずです。

```
データ構造:
  { id: string, text: string, done: boolean, createdAt: number }

状態:
  todos: Todo[]        タスクの配列
  filter: string       "all" | "active" | "done"
  editingId: string|null  編集中のタスクID

関数の役割:
  - storage.load() / storage.save()   永続化
  - addTodo(text)                      追加
  - toggleTodo(id)                     完了切り替え
  - deleteTodo(id)                     削除
  - updateTodo(id, text)               編集
  - clearCompleted()                   完了分を一括削除
  - getVisibleTodos()                  絞り込み後の配列を返す
  - render()                           画面を描き直す

実装順:
  1. データ構造と state を定義
  2. render() を作り、固定データで表示できるようにする
  3. 追加機能
  4. 完了・削除
  5. 絞り込み
  6. localStorage
  7. 編集（最後。いちばん複雑）
```

> 💡 **この設計を、自分で評価してください。**
> - `id` はなぜ必要か？ → 削除・切り替えの対象を特定するため
> - なぜ `editingId` を状態に持つのか？ → DOM に状態を持たせないため
> - なぜ `getVisibleTodos()` を分けるのか？ → `render()` を単純に保つため
>
> **納得できない部分は、必ず質問してください。**「なぜ id が必要なのですか？」と聞くだけでOKです。

## ✍️ 手を動かす④ ─ ステップ3：詰まった部分だけ書かせる

### ダメな聞き方

```text
❌ ToDoアプリのJavaScriptを書いてください
```

→ 200行のコードが返ってきて、理解できないまま終わります。

> 🆘 **ここで詰まったら**（AIが一気に大量のコードを出してきて、理解が追いつかない）
> - **やること**：**依頼を小さく割る**。「アプリ全体」ではなく「この1つの関数だけ」「この1機能だけ」と範囲を絞って聞き直す
> - **こう頼み直す**：
>   「さっきは全部のコードを出してくれましたが、理解が追いつきません。○○の機能**だけ**に絞って、まず実装方針を説明し、そのあとで短いコードを、各行のコメント付きで示してください」
> - 理解できないコードは、この教材のルール上 **使わない**。「1機能ずつ・説明させてから」が鉄則です。

### 良い聞き方

```text
ToDoアプリを作っています。以下の関数の実装で詰まっています。

【やりたいこと】
タスクをインライン編集する機能。
タスクのテキストをダブルクリックすると input に変わり、
Enter で確定、Esc でキャンセル、フォーカスが外れたら確定。

【現在のコード】
（自分が書いたところまでを貼る）

【状態】
let todos = [];        // { id, text, done, createdAt }
let editingId = null;  // 編集中のタスクID

【制約】
- render() で innerHTML を毎回書き換える設計です
- イベント委譲を使っています
- ユーザー入力は escapeHtml() でエスケープしています

【聞きたいこと】
1. 編集モードの実装で、注意すべき点を教えてください
   （render() で書き換えると input が消える問題など）
2. 実装の方針を教えてください
3. そのうえで、コードを示してください
4. 各行に、なぜそう書くかのコメントを付けてください
```

**ポイント**

| 要素 | 効果 |
| --- | --- |
| 詰まっている部分を**限定**する | 200行ではなく20行が返る |
| 現在のコードを**全部**貼る | 既存の設計に合った回答になる |
| **制約**を書く | 設計を壊す提案を防げる |
| **注意点を先に聞く** | コードを読む前に、見るべき箇所がわかる |
| コメントを要求する | 理解しながら読める |

## ✍️ 手を動かす⑥ ─ 実践：AIの出力を採点する

以下は、**AIに「ToDoアプリを作って」と丸投げしたときに、実際に返ってきがちなコード**です。
**7つの問題**があります。すべて指摘してください。

```html
<div id="app">
  <input type="text" id="input">
  <button onclick="addTodo()">追加</button>
  <ul id="list"></ul>
</div>

<script>
  var todos = [];

  function addTodo() {
    var text = document.getElementById("input").value;
    if (text == "") {
      alert("入力してください");
      return;
    }
    todos.push({ id: todos.length, text: text, done: false });
    localStorage.setItem("todos", JSON.stringify(todos));
    render();
  }

  function render() {
    var list = document.getElementById("list");
    list.innerHTML = "";
    for (var i = 0; i < todos.length; i++) {
      list.innerHTML += '<li>' + todos[i].text +
        ' <button onclick="deleteTodo(' + i + ')">削除</button></li>';
    }
  }

  function deleteTodo(i) {
    todos.splice(i, 1);
    render();
  }

  todos = JSON.parse(localStorage.getItem("todos"));
  render();
</script>
```

<details>
<summary>答えを見る（自力で7つ探してから開いてください）</summary>

### 🔴 高：XSS 脆弱性

```javascript
list.innerHTML += '<li>' + todos[i].text + ...
```

ユーザーが `<img src=x onerror="...">` と入力すると、**スクリプトが実行されます。**
`textContent` を使うか、`escapeHtml()` でエスケープする必要があります。

### 🔴 高：初回アクセスでクラッシュする

```javascript
todos = JSON.parse(localStorage.getItem("todos"));
```

初回は `null` が返るため、`todos` が `null` になり、`render()` の `todos.length` でエラー。
**しかも `try...catch` がないので、シークレットモードでも落ちます。**

```javascript
// 修正
const loadTodos = () => {
  try {
    return JSON.parse(localStorage.getItem("todos") ?? "[]") ?? [];
  } catch {
    return [];
  }
};
todos = loadTodos();
```

### 🔴 高：ID が壊れる

```javascript
todos.push({ id: todos.length, ... });
```

3件あるとき `id` は 0,1,2。1件消して追加すると、**id が重複します**（0,2 の状態で length は 2）。
`crypto.randomUUID()` か `Date.now()` を使うべきです。

### 🟡 中：削除がインデックス依存

```javascript
deleteTodo(i)  // 配列のインデックス
```

絞り込み機能を足した瞬間に壊れます。**id で指定する**べきです。

```javascript
const deleteTodo = (id) => {
  todos = todos.filter((t) => t.id !== id);
};
```

### 🟡 中：`onclick` 属性を使っている

HTMLとJSが混ざり、関数がグローバルスコープに晒されます。
また、`onclick="deleteTodo(0)"` は**文字列を組み立てているため、値によっては壊れます**。
**イベント委譲**にすべきです。

### 🟡 中：`localStorage` の保存漏れ

`deleteTodo` で保存していません。**削除してリロードすると復活します。**

### 🟢 低：`var` と `==`

`var` は関数スコープで事故のもと。`==` は型変換で意図しない判定をします。
`const` / `let` と `===` を使うべきです。

### おまけ：`innerHTML +=` の非効率

ループの中で `innerHTML +=` すると、**毎回HTML全体を再パースします**。
`map().join("")` で一度に組み立てるべきです。

### おまけ：アクセシビリティ

- `<input>` に `<label>` がない
- `alert()` はUXが悪い（画面内にエラー表示すべき）
- 削除ボタンに「何を削除するか」の情報がない（`aria-label`）

</details>

> ⚠️ **このコードは「動きます」。** 追加も削除も保存もできます。
> だから初学者は「できた」と思ってしまいます。
> **動くことと、正しいことは別**です。これがこのレッスンの結論です。
