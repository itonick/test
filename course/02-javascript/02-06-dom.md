## 📖 DOM とは

ブラウザは、HTMLを読み込むと**木構造のオブジェクト**に変換します。これが **DOM（Document Object Model）** です。

```
document
└─ html
   ├─ head
   │  └─ title
   └─ body
      ├─ h1
      └─ ul
         ├─ li
         └─ li
```

**JavaScript はこの木を操作します。** HTMLファイルそのものを書き換えるわけではありません。

> 💡 **重要**：DOM操作の結果は**リロードすると消えます**。
> ファイルは変わっていないからです。データを残したいなら、`localStorage`（2-11）かサーバー（第3部）が必要です。

### 取得できたか必ず確認する

```javascript
const el = document.querySelector("#not-exist");
console.log(el);        // null
el.textContent = "a";   // ❌ TypeError: Cannot read properties of null
```

> ⚠️ **第2部で最も多いエラーがこれです。**
>
> **原因は2つだけ**
> 1. **セレクタの書き間違い**（`#btn` と `.btn`、つづりミス）
> 2. **`<script>` が HTML より先に実行されている**（`defer` を付けていない）
>
> **確認方法**
> ```javascript
> const el = document.querySelector("#btn");
> console.log(el);   // null なら取れていない
> ```

> 🆘 **ここで詰まったら**（`Cannot read properties of null` が消えない）
> - **まず確認**：上の `console.log(el)` が `null` を出すなら「取れていない」。セレクタのつづり（`#` と `.` の違い）と、`<script>` に `defer` が付いているかを見直す
> - **直らなければ、AIにこう聞く**（HTMLと該当JSの両方を貼る）：
>   「`Cannot read properties of null` が出ます。querySelector が null を返す原因を、私のHTMLとJSを見て指摘してください。すぐ直すのではなく、どこを確認すべきか教えてください」

### NodeList の扱い

```javascript
const texts = document.querySelectorAll(".text");

console.log(texts.length);   // 2
console.log(texts[0]);       // 最初の要素

// forEach は使える
texts.forEach((el) => {
  el.classList.add("highlight");
});

// map / filter は使えない → 配列に変換する
const arr = [...texts];              // または Array.from(texts)
const contents = arr.map((el) => el.textContent);
```

> ⚠️ **NodeList は配列ではありません。** `forEach` は使えますが、`map` `filter` は使えません。
> `[...nodeList]` で配列に変換してください。

### テキストを変える

```javascript
const title = document.querySelector("#title");

title.textContent = "新しいタイトル";     // ✅ 安全
title.innerHTML = "<b>太字</b>";          // ⚠️ HTMLとして解釈される

```

| プロパティ | HTMLを解釈するか | 安全性 | 速度 |
| --- | --- | --- | --- |
| **`textContent`** | しない（そのまま文字として表示） | **安全** | 速い |
| `innerHTML` | **する** | **危険** | 遅い |
| `innerText` | しない | 安全 | 遅い |

### ⚠️ XSS（クロスサイトスクリプティング）

**これは第2部で最も重要なセキュリティの話です。**

```javascript
// ユーザーが入力した値
const userInput = '<img src=x onerror="alert(\'攻撃されました\')">';

element.innerHTML = userInput;      // ❌ スクリプトが実行される
element.textContent = userInput;    // ✅ ただの文字として表示される
```

`innerHTML` は、渡された文字列を**HTMLとして解釈して実行**します。ユーザーの入力をそのまま渡すと、

- Cookie を盗まれる（なりすまし）
- 偽のログインフォームを表示される
- 勝手に投稿・送金される

**鉄則**

> **ユーザー入力を表示するときは、必ず `textContent` を使う。**
> `innerHTML` を使ってよいのは、**自分が書いた固定の文字列だけ**。

### `innerHTML` をどうしても使いたいとき

HTMLタグ付きで組み立てたい場合は、**変数部分だけをエスケープ**します。

```javascript
const escapeHtml = (str) => {
  return String(str)
    .replaceAll("&", "&amp;")
    .replaceAll("<", "&lt;")
    .replaceAll(">", "&gt;")
    .replaceAll('"', "&quot;")
    .replaceAll("'", "&#39;");
};

// 使い方
element.innerHTML = `<p class="name">${escapeHtml(userInput)}</p>`;
```

> 💡 **この `escapeHtml` 関数は、これから何度も使います。** 自分のスニペット集に保存してください。
> 第3部では、PHP の `htmlspecialchars()` として同じ話が出てきます。

## ✍️ 手を動かす③ ─ 要素を作る・追加する・消す

```javascript
// 作る
const li = document.createElement("li");
li.textContent = "新しい項目";
li.classList.add("card");

// 追加する
const list = document.querySelector("#list");
list.appendChild(li);        // 末尾に追加
list.prepend(li);            // 先頭に追加
list.append(li1, li2);       // 複数まとめて追加（文字列もOK）

// 特定の位置に
existingEl.before(newEl);    // 直前に
existingEl.after(newEl);     // 直後に
existingEl.replaceWith(newEl); // 置き換え

// 消す
li.remove();                 // その要素を削除
list.innerHTML = "";         // 中身を全部消す（よく使う）
```

### 複数要素を効率よく追加する

```javascript
// ❌ ループの中で毎回 appendChild すると、毎回再描画される（遅い）
for (const item of items) {
  const li = document.createElement("li");
  li.textContent = item.name;
  list.appendChild(li);
}

// ✅ 方法1：文字列を組み立てて1回で入れる
list.innerHTML = items
  .map((item) => `<li>${escapeHtml(item.name)}</li>`)
  .join("");

// ✅ 方法2：DocumentFragment を使う（安全性も速度も両立）
const frag = document.createDocumentFragment();
for (const item of items) {
  const li = document.createElement("li");
  li.textContent = item.name;   // ← textContent なので安全
  frag.appendChild(li);
}
list.replaceChildren(frag);
```

> 💡 **`replaceChildren()` は「中身を全部入れ替える」メソッド**です。
> `innerHTML = ""` してから `appendChild` するより簡潔で速いです。

## ✍️ 手を動かす④ ─ レンダリングの考え方

**DOM操作で最も大事な設計原則。**

```
❌ 悪い設計：DOMを直接いじり回す
   「ボタンが押されたら、この li の textContent を変えて、
    class を足して、隣の span の数字を +1 して…」
   → 状態がどこにあるかわからなくなる

✅ 良い設計：データを更新して、画面全部を描き直す
   「ボタンが押されたら、データを更新する → 画面を描き直す」
   → データが唯一の真実（Single Source of Truth）
```

### パターン

```javascript
// ① 状態（データ）
let items = [
  { id: 1, name: "牛乳", done: false },
  { id: 2, name: "パン", done: true },
];

// ② 描画する関数（データ → 画面）
const render = () => {
  const list = document.querySelector("#list");
  list.innerHTML = items
    .map((item) => `
      <li class="card ${item.done ? "done" : ""}" data-id="${item.id}">
        <span>${escapeHtml(item.name)}</span>
      </li>
    `)
    .join("");
};

// ③ 操作はデータを変えて、render を呼ぶだけ
const addItem = (name) => {
  items = [...items, { id: Date.now(), name, done: false }];
  render();
};

const toggleItem = (id) => {
  items = items.map((item) =>
    item.id === id ? { ...item, done: !item.done } : item
  );
  render();
};

// 初回描画
render();
```

> 💡 **これが React などのフレームワークの基本的な考え方**でもあります。
> 「データを変える → 画面を作り直す」。この一方通行を守ると、バグが激減します。

**メリット**

| 点 | 理由 |
| --- | --- |
| バグが減る | 画面とデータがずれない |
| コードが読める | 「いまの画面 = いまのデータ」が保証される |
| テストしやすい | データの変換だけをテストできる |

## ✍️ 手を動かす⑤ ─ 実践：メニュー一覧を描画する

`js/dom.js` に書いてください。

> 🖊 **手で打ってください。** 完成形は `code/02-06/js/dom.js`（📋 コピペ可）。

```javascript
// ==========================================================
// ユーティリティ
// ==========================================================

/** HTMLエスケープ（XSS対策） */
const escapeHtml = (str) =>
  String(str)
    .replaceAll("&", "&amp;")
    .replaceAll("<", "&lt;")
    .replaceAll(">", "&gt;")
    .replaceAll('"', "&quot;")
    .replaceAll("'", "&#39;");

// ==========================================================
// データ（状態）
// ==========================================================

const MENU = [
  { id: "drip",  name: "ハンドドリップ", price: 600, category: "coffee", soldOut: false },
  { id: "latte", name: "カフェラテ",     price: 600, category: "coffee", soldOut: false },
  { id: "cake",  name: "本日のケーキ",   price: 550, category: "food",   soldOut: true  },
  { id: "tea",   name: "季節のお茶",     price: 500, category: "tea",    soldOut: false },
  { id: "toast", name: "厚切りトースト", price: 450, category: "food",   soldOut: false },
];

// 表示条件（これも「状態」）
let filter = {
  category: "all",
  hideSoldOut: false,
};

// ==========================================================
// 描画
// ==========================================================

const output = document.querySelector("#output");

/** データを条件で絞り込む */
const getVisibleMenu = () => {
  return MENU
    .filter((m) => filter.category === "all" || m.category === filter.category)
    .filter((m) => !filter.hideSoldOut || !m.soldOut);
};

/** 1件分のHTMLを作る */
const menuItemHtml = (item) => `
  <div class="card ${item.soldOut ? "sold-out" : ""}" data-id="${item.id}">
    <strong>${escapeHtml(item.name)}</strong>
    <span>¥${item.price.toLocaleString()}</span>
    ${item.soldOut ? '<span class="badge">売り切れ</span>' : ""}
  </div>
`;

/** 画面を描き直す */
const render = () => {
  const items = getVisibleMenu();

  if (items.length === 0) {
    output.innerHTML = '<p class="empty">該当する商品がありません</p>';
    return;
  }

  output.innerHTML = items.map(menuItemHtml).join("");
};

// ==========================================================
// 初回描画
// ==========================================================

render();

// ==========================================================
// 動作確認（Console で実行してみてください）
// ==========================================================
// filter.category = "coffee"; render();
// filter.hideSoldOut = true;  render();
// filter = { category: "all", hideSoldOut: false }; render();
```

1. ブラウザで `dom.html` を開く
2. Console に `filter.category = "coffee"; render();` と入力
3. 表示が変わることを確認

> 💡 **Console から関数を呼べる**のは、デバッグでとても便利です。

## ⚠️ つまずきポイントまとめ

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `Cannot read properties of null` | 要素が取得できていない | `console.log(el)` で確認。`defer` とセレクタを確認 |
| `map is not a function` | NodeList に map を使った | `[...nodeList]` で配列化 |
| `input` の値が取れない | `textContent` を使っている | `value` を使う |
| HTMLタグが文字として表示される | `textContent` を使っている | 意図通りなら正しい。HTMLにしたいなら `innerHTML` |
| スクリプトが実行されてしまう | `innerHTML` にユーザー入力を渡した | `textContent` か `escapeHtml` |
| CSSから上書きできない | `style` で直接指定した | `classList` を使う |
| 追加した要素が表示されない | `appendChild` を忘れた | 作っただけでは表示されない |
| 描画が遅い | ループ内で毎回 appendChild | まとめて1回で入れる |
| リロードすると消える | DOM操作はメモリ上だけ | localStorage（2-11）かサーバー（第3部） |

- [ ] 並び替えを追加する（`filter.sort` に `"price-asc"` / `"price-desc"` / `"default"`）
- [ ] 表示件数を `#count` 要素に出す（「5件中3件を表示」の形式）
- [ ] 0件のときは「該当する商品がありません」と表示する（実装済み。動作確認する）

> 💡 これらはすべて **`getVisibleMenu()` の中と `render()` の中だけ**で完結します。
> **データを変える → 描き直す**、の設計になっていれば、UIを足すのは簡単です。
