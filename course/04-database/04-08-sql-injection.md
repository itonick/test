## 📖 なぜこれが最重要なのか

第3部で XSS を学びました。XSS は「**そのユーザーの画面**」が乗っ取られます。

**SQLインジェクションは、「データベース全体」が奪われます。**

| 攻撃 | 被害 |
| --- | --- |
| XSS | そのユーザーのCookie、画面 |
| **SQLインジェクション** | **全ユーザーの個人情報、パスワードハッシュ、全データの改ざん・削除** |

実際に起きた被害の例（一般に報道された類型）：

- 数百万件の会員情報が流出
- 全データを削除され、サービスが停止
- 認証を回避され、管理画面に侵入される

> ⚠️ **「小さいサイトだから狙われない」は誤りです。**
> 攻撃は自動化されており、**ボットが無差別にスキャン**しています。
> 公開した瞬間から、攻撃を受けます。

## ✍️ 手を動かす① ─ 実際に攻撃を成立させる

**読むだけでなく、必ず自分の環境で実行してください。**

### 脆弱なコード

`code/04-08/injection-demo.php` を使います（📋 コピペ可）。
**自分のローカル環境でのみ実行してください。**

```php
<?php
// ❌ 脆弱な実装：値を文字列連結でSQLに埋め込んでいる
$email    = $_POST["email"] ?? "";
$password = $_POST["password"] ?? "";

$sql = "SELECT * FROM users WHERE email = '{$email}' AND password = '{$password}'";
$user = $pdo->query($sql)->fetch();

if ($user !== false) {
    echo "ログイン成功: " . $user["name"];
} else {
    echo "ログイン失敗";
}
```

### 攻撃1：認証を回避する

**メールアドレス欄に、以下を入力してください。**

```
' OR '1'='1
```

**パスワードは適当な文字列で構いません。**

### 何が起きたか

組み立てられたSQLは、こうなります。

```sql
SELECT * FROM users WHERE email = '' OR '1'='1' AND password = 'なんでもいい'
```

**`'1'='1'` は常に真**です。`AND` より `OR` のほうが優先度が低いため、

```sql
WHERE (email = '') OR ('1'='1' AND password = '...')
```

とはならず、`'1'='1'` が効いて**全ユーザーが該当**します。
`fetch()` は最初の1件を返すため、**先頭のユーザーとしてログインできてしまいます**。

### 攻撃2：パスワードの条件を消す

```
' OR 1=1 -- 
```

> ⚠️ **末尾に半角スペースが必要です**（`--` の後ろ）。MySQL のコメント記法の仕様です。

```sql
SELECT * FROM users WHERE email = '' OR 1=1 -- ' AND password = '...'
                                            └─────ここから先はコメント────┘
```

**`--` 以降が全部コメントになり、パスワードの条件が消えます。**

### 攻撃3：管理者としてログインする

```
taro@example.com' -- 
```

```sql
SELECT * FROM users WHERE email = 'taro@example.com' -- ' AND password = '...'
```

**パスワードを知らなくても、メールアドレスさえ分かればログインできます。**

### 攻撃4：他のテーブルの情報を盗む（UNION攻撃）

```
' UNION SELECT 1,'x','y',password_hash,0,0,0,0 FROM users -- 
```

**`UNION` で別のクエリの結果を混ぜ込み、パスワードハッシュを画面に表示させます。**

> 💡 カラム数と型を合わせる必要があるため、攻撃者は何度も試行します。
> エラーメッセージが表示されていると、**カラム数を教えてしまう**ことになります。
> （4-7 で「エラーの詳細を画面に出さない」と書いた理由の1つです）
