## 📖 PDO を使う理由

PHPからデータベースを操作する方法は3つあります。

| 方法 | 評価 |
| --- | --- |
| `mysql_*` 関数 | ❌ **PHP 7.0 で削除済み**。使えない |
| `mysqli` | △ MySQL専用。使えるが、PDOのほうが書きやすい |
| **PDO** | ✅ **これを使う**。複数のDBに対応。標準的 |

> ⚠️ **ネット上の古い記事には `mysql_query()` が出てきます。**
> これは**削除された関数**です。動きません。
> 「`mysql_connect`」で検索して出てくる記事は、10年以上前のものです。無視してください。

**PDO の利点**

- MySQL / PostgreSQL / SQLite などを同じコードで扱える
- プレースホルダの書き方が統一されている
- 例外でエラーを扱える

## ✍️ 手を動かす① ─ 接続する

### 最小の接続

```php
<?php
declare(strict_types=1);

$dsn = "mysql:host=localhost;dbname=board_app;charset=utf8mb4";
$pdo = new PDO($dsn, "root", "");
```

**これでは不十分です。** 必ず以下の設定を付けてください。

### 正しい接続（📋 コピペして使ってください）

```php
<?php
declare(strict_types=1);

$dsn = "mysql:host=localhost;dbname=board_app;charset=utf8mb4";

$pdo = new PDO($dsn, "root", "", [
    // ① エラーを例外として投げる（★ 最重要）
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,

    // ② 連想配列で取得する（数値キーを併せて返さない）
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,

    // ③ 本物のプレースホルダを使う（★ セキュリティ上重要）
    PDO::ATTR_EMULATE_PREPARES   => false,

    // ④ 数値を文字列ではなく数値型で返す（PHP 8.1以降で既定だが明示する）
    PDO::ATTR_STRINGIFY_FETCHES  => false,
]);
```

> 🆘 **ここで詰まったら**（接続の段階でエラーが出る）
> - **`could not find driver`**：PDOのMySQLドライバが無効。XAMPP/MAMPには通常入っていますが、独自環境なら `php.ini` の `extension=pdo_mysql` の行頭の `;` を外して再起動
> - **`SQLSTATE[HY000] [2002]`**：MySQL が起動していない／ホスト・ポート違い。MAMPは `host=localhost` でダメなら `127.0.0.1` とポート `8889` を試す
> - **`Access denied` / `Unknown database`**：ユーザー/パスワード（4-2の表）か `dbname` の指定ミス
> - **直らなければ、AIにこう聞く**（DSN・OS・XAMPP/MAMPの別を添え、パスワードは伏せる）：
>   「PDOでMySQLに接続できません。エラーは○○です。DSNはこれです（値は伏せます）。原因の候補を確認手順つきで教えてください」

### 4つの設定の意味

#### ① `ATTR_ERRMODE => ERRMODE_EXCEPTION`

**これがないと、エラーが黙って無視されます。**

```php
// 設定なし（既定は ERRMODE_SILENT）
$stmt = $pdo->query("SELECT * FROM 存在しないテーブル");
var_dump($stmt);       // false が返るだけ。エラーは出ない
$stmt->fetchAll();     // ❌ Fatal error: Call to a member function on bool
```

**エラーの原因が「false に対するメソッド呼び出し」として現れるため、
本当の原因（テーブルがない）にたどり着けません。**

```php
// ERRMODE_EXCEPTION なら
try {
    $pdo->query("SELECT * FROM 存在しないテーブル");
} catch (PDOException $e) {
    echo $e->getMessage();
    // → SQLSTATE[42S02]: Base table or view not found: 1146 Table 'board_app.存在しないテーブル' doesn't exist
}
```

> ⚠️ **`ERRMODE_EXCEPTION` は必ず設定してください。** 例外はありません。

#### ② `ATTR_DEFAULT_FETCH_MODE => FETCH_ASSOC`

```php
// 既定（FETCH_BOTH）：同じデータが2倍返ってくる
['id' => 1, 0 => 1, 'name' => '太郎', 1 => '太郎']

// FETCH_ASSOC：連想配列だけ
['id' => 1, 'name' => '太郎']
```

**メモリの無駄が半分になり、`var_dump` も見やすくなります。**

#### ③ `ATTR_EMULATE_PREPARES => false`

**これはセキュリティに関わります。**

| 設定 | 挙動 |
| --- | --- |
| `true`（既定） | **PHPが文字列を組み立てて**サーバーに送る（エミュレーション） |
| **`false`** | **SQLと値を別々に**サーバーへ送る（本物のプレースホルダ） |

`false` にすると、**SQLと値が混ざる余地が原理的になくなります**。詳しくは 4-8 で扱います。

> 💡 **`false` にすると、`LIMIT ?` に整数を渡せるようになる**という実用的な利点もあります。
> エミュレーションモードでは `LIMIT '10'` と文字列になり、構文エラーになります。

#### ④ `ATTR_STRINGIFY_FETCHES => false`

```php
// true（PHP 8.0 までの既定）
['id' => '1', 'price' => '600']     // 数値なのに文字列

// false
['id' => 1, 'price' => 600]         // 数値のまま
```

**`declare(strict_types=1)` と組み合わせると、型の取り違えを防げます。**

## ✍️ 手を動かす② ─ 接続情報を分離する

**接続情報をソースコードに直接書いてはいけません。**

```php
// ❌ これをGitにコミットしてはいけない
$pdo = new PDO($dsn, "root", "本番のパスワード");
```

### `.env` ファイルを使う

```
board/
├─ .env             ← ★ Git管理しない（.gitignore に入れる）
├─ .env.example     ← Git管理する（雛形）
├─ config/
│   └─ database.php
└─ public/
```

**`.env`**（実際の値。**絶対にコミットしない**）

```
DB_HOST=localhost
DB_PORT=3306
DB_NAME=board_app
DB_USER=root
DB_PASS=
```

**`.env.example`**（雛形。これはコミットする）

```
DB_HOST=localhost

DB_USER=
DB_PASS=
```

**`.gitignore`**

```

```

> ⚠️ **`.env` を `public/` の中に置かないでください。**
> `http://example.com/.env` でダウンロードされます。
> **公開ディレクトリの外に置く**のが鉄則です（3-12 と同じ原則）。

### `.env` を読み込む

Composer のライブラリ（`vlucas/phpdotenv`）を使うのが一般的ですが、
**仕組みを理解するために、まず自分で書きます。**

```php
<?php
declare(strict_types=1);

/**
 * .env ファイルを読み込んで連想配列で返す
 */
function load_env(string $path): array
{
    if (!is_file($path)) {
        throw new RuntimeException(".env ファイルが見つかりません: {$path}");
    }

    $env = [];
    $lines = file($path, FILE_IGNORE_NEW_LINES | FILE_SKIP_EMPTY_LINES);

    foreach ($lines as $line) {
        $line = trim($line);

        // コメント行と、= を含まない行は無視する
        if ($line === "" || str_starts_with($line, "#") || !str_contains($line, "=")) {
            continue;
        }

        [$key, $value] = explode("=", $line, 2);   // 値に = が含まれても大丈夫
        $env[trim($key)] = trim($value, " \t\"'");  // クォートを除去
    }

    return $env;
}
```

### `config/database.php`

```php
<?php
declare(strict_types=1);

require_once __DIR__ . "/../lib/env.php";

/**
 * データベース接続を返す（1リクエスト中は同じ接続を使い回す）
 */
function db(): PDO
{
    static $pdo = null;         // ★ 静的変数で使い回す

    if ($pdo !== null) {
        return $pdo;
    }

    $env = load_env(__DIR__ . "/../.env");

    $host    = $env["DB_HOST"] ?? "localhost";
    $port    = $env["DB_PORT"] ?? "3306";
    $dbname  = $env["DB_NAME"] ?? "";
    $user    = $env["DB_USER"] ?? "root";
    $pass    = $env["DB_PASS"] ?? "";

    $dsn = "mysql:host={$host};port={$port};dbname={$dbname};charset=utf8mb4";

    try {
        $pdo = new PDO($dsn, $user, $pass, [
            PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
            PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
            PDO::ATTR_EMULATE_PREPARES   => false,
            PDO::ATTR_STRINGIFY_FETCHES  => false,
        ]);
    } catch (PDOException $e) {
        // ★ 例外メッセージには接続情報が含まれるため、画面に出さない
        error_log("DB接続に失敗しました: " . $e->getMessage());
        http_response_code(503);
        exit("ただいまシステムが混み合っています。しばらくしてからお試しください。");
    }

    return $pdo;
}
```

### ⚠️ 接続エラーのメッセージを画面に出してはいけない

```
SQLSTATE[HY000] [1045] Access denied for user 'root'@'localhost' (using password: YES)
```

**このメッセージには、ユーザー名・ホスト名・パスワードを使ったかどうかが含まれます。**
攻撃者にとっては貴重な情報です。

> 💡 **原則**：詳細はログへ、画面には一般的なメッセージを。
> これは 3-12 で学んだ「想定外のエラー」の扱いと同じです。

### `static` で接続を使い回す理由

```php
static $pdo = null;
```

**接続は重い処理です。** 1リクエスト中に10回 `db()` を呼んでも、
接続は1回だけ行われます。

## ✍️ 手を動かす③ ─ データを取得する

### `query()` — 値を埋め込まない場合

```php
<?php
$pdo = db();

// 全件取得
$stmt = $pdo->query("SELECT id, name, body FROM posts ORDER BY created_at DESC");
$posts = $stmt->fetchAll();

foreach ($posts as $post) {
    echo e($post["name"]) . "<br>";
}
```

> ⚠️ **`query()` は、値を埋め込まないクエリだけに使ってください。**
> 値を埋め込む場合は、必ず `prepare()` + `execute()` を使います（次項）。

### `prepare()` + `execute()` — 値を埋め込む場合

```php
<?php
// ? プレースホルダ
$stmt = $pdo->prepare("SELECT * FROM posts WHERE user_id = ? AND created_at >= ?");
$stmt->execute([5, "2026-04-01"]);
$posts = $stmt->fetchAll();

// 名前付きプレースホルダ（★ 推奨）
$stmt = $pdo->prepare(
    "SELECT * FROM posts WHERE user_id = :user_id AND created_at >= :since"
);
$stmt->execute([
    "user_id" => 5,
    "since"   => "2026-04-01",
]);
$posts = $stmt->fetchAll();
```

> 💡 **名前付きプレースホルダを推奨します。**
> 引数が増えても順番を間違えません。同じ値を複数回使うこともできます。
>
> ```php
> $stmt = $pdo->prepare(
>     "SELECT * FROM posts WHERE name LIKE :kw OR body LIKE :kw"
> );
> $stmt->execute(["kw" => "%テスト%"]);   // ← 1回渡すだけで両方に入る
> ```

### 取得のメソッド

```php
<?php
// 全件を配列で
$posts = $stmt->fetchAll();
// → [['id'=>1,...], ['id'=>2,...]]  0件なら []

// 1件だけ
$post = $stmt->fetch();
// → ['id'=>1,...]  無ければ false

// 1つの値だけ
$count = (int) $pdo->query("SELECT COUNT(*) FROM posts")->fetchColumn();
// → 12

// 1カラムを配列で
$stmt = $pdo->query("SELECT name FROM posts");
$names = $stmt->fetchAll(PDO::FETCH_COLUMN);
// → ['山田太郎', '名無しさん', ...]

// キー => 値 の連想配列
$stmt = $pdo->query("SELECT id, name FROM posts");
$map = $stmt->fetchAll(PDO::FETCH_KEY_PAIR);
// → [1 => '山田太郎', 2 => '名無しさん', ...]
```

> ⚠️ **`fetch()` は「見つからないとき `false`」を返します。**
>
> ```php
> $post = $stmt->fetch();
> if ($post === false) {          // ✅ 厳密に比較する
>     http_response_code(404);
>     exit("投稿が見つかりません");
> }
>
> if (!$post) { }                 // ⚠️ 動くが、空配列と区別できない
> ```

### ループで取得する（大量データ向け）

```php
<?php
// ❌ 100万件を fetchAll() すると、全部メモリに載る
$all = $pdo->query("SELECT * FROM huge_table")->fetchAll();

// ✅ 1行ずつ処理する（メモリを食わない）
$stmt = $pdo->query("SELECT * FROM huge_table");
while ($row = $stmt->fetch()) {
    process($row);
}
```

**これが、4-1 で見た「ファイル保存のメモリ問題」への回答です。**
データベースは、1行ずつ受け取れます。

## ✍️ 手を動かす④ ─ データを追加・更新・削除する

```php
<?php
// ---------- 追加 ----------
$stmt = $pdo->prepare(
    "INSERT INTO posts (user_id, name, body, edit_token)
     VALUES (:user_id, :name, :body, :edit_token)"
);
$stmt->execute([
    "user_id"    => $user_id,          // null でもよい
    "name"       => $name,
    "body"       => $body,
    "edit_token" => bin2hex(random_bytes(16)),
]);

// 追加された行のIDを取得
$new_id = (int) $pdo->lastInsertId();

// ---------- 更新 ----------
$stmt = $pdo->prepare("UPDATE posts SET body = :body WHERE id = :id");
$stmt->execute(["body" => $body, "id" => $id]);

// 実際に更新された行数
$affected = $stmt->rowCount();
if ($affected === 0) {
    // 該当する行がなかった、または値が変わらなかった
}

// ---------- 削除 ----------
$stmt = $pdo->prepare("DELETE FROM posts WHERE id = :id");
$stmt->execute(["id" => $id]);
$deleted = $stmt->rowCount() > 0;
```

> ⚠️ **`rowCount()` は「実際に変更された行数」です。**
> 値が変わらない UPDATE では 0 になります（4-4 で扱った MySQL の仕様）。
> **「更新できたか」の判定に使うと、同じ値での更新を失敗と誤判定します。**

## ✍️ 手を動かす⑤ ─ LIMIT とプレースホルダ

**初学者が必ずハマる箇所です。**

```php
<?php
// ❌ エミュレーションモードだと、LIMIT '10' になって構文エラー
$stmt = $pdo->prepare("SELECT * FROM posts LIMIT ?");
$stmt->execute([10]);
```

### 対処1：`ATTR_EMULATE_PREPARES => false` にする（推奨）

**最初の接続設定で `false` にしていれば、そのまま動きます。**

```php
$stmt = $pdo->prepare("SELECT * FROM posts ORDER BY id LIMIT :limit OFFSET :offset");
$stmt->execute(["limit" => 10, "offset" => 20]);   // ✅ 動く
```

### 対処2：`bindValue` で型を明示する

```php
$stmt = $pdo->prepare("SELECT * FROM posts LIMIT :limit");
$stmt->bindValue(":limit", 10, PDO::PARAM_INT);    // ★ 型を指定
$stmt->execute();
```

### 対処3：整数にキャストして埋め込む

```php
// LIMIT / OFFSET は整数であることが保証できるなら、これも許容される
$limit  = max(1, min(100, (int) ($_GET["limit"] ?? 10)));
$offset = max(0, (int) ($_GET["offset"] ?? 0));

$stmt = $pdo->query("SELECT * FROM posts ORDER BY id LIMIT {$limit} OFFSET {$offset}");
```

> ⚠️ **対処3は、「必ず整数である」ことを保証した場合のみ許されます。**
> `(int)` でキャストし、範囲も制限してください。
> **文字列を直接埋め込むのは、絶対にやってはいけません**（4-8で扱います）。

## ✍️ 手を動かす⑥ ─ トランザクション

```php
<?php
$pdo = db();

try {
    $pdo->beginTransaction();

    // 投稿を削除
    $stmt = $pdo->prepare("DELETE FROM posts WHERE id = :id");
    $stmt->execute(["id" => $id]);

    // カウンタを減らす
    $stmt = $pdo->prepare("UPDATE users SET post_count = post_count - 1 WHERE id = :uid");
    $stmt->execute(["uid" => $user_id]);

    $pdo->commit();

} catch (Throwable $e) {
    $pdo->rollBack();               // ★ 巻き戻す
    error_log("削除に失敗: " . $e->getMessage());
    throw $e;                       // 呼び出し元に知らせる
}
```

### 安全なヘルパーを作る

```php
<?php
/**
 * トランザクション内で処理を実行する。
 * 例外が出たら自動でロールバックする。
 *
 * @template T
 * @param callable(PDO): T $callback
 * @return T
 */
function transaction(PDO $pdo, callable $callback): mixed
{
    // すでにトランザクション中ならネストしない
    if ($pdo->inTransaction()) {
        return $callback($pdo);
    }

    $pdo->beginTransaction();

    try {
        $result = $callback($pdo);
        $pdo->commit();
        return $result;
    } catch (Throwable $e) {
        if ($pdo->inTransaction()) {
            $pdo->rollBack();
        }
        throw $e;
    }
}
```

**使う側**

```php
$new_id = transaction($pdo, function (PDO $pdo) use ($name, $body, $tag_ids) {
    $stmt = $pdo->prepare(
        "INSERT INTO posts (name, body, edit_token) VALUES (:name, :body, :token)"
    );
    $stmt->execute([
        "name"  => $name,
        "body"  => $body,
        "token" => bin2hex(random_bytes(16)),
    ]);

    $post_id = (int) $pdo->lastInsertId();

    // タグを紐付ける
    $stmt = $pdo->prepare("INSERT INTO post_tag (post_id, tag_id) VALUES (:pid, :tid)");
    foreach ($tag_ids as $tag_id) {
        $stmt->execute(["pid" => $post_id, "tid" => $tag_id]);
    }

    return $post_id;
});
```

> 💡 **「投稿とタグを同時に登録する」のような複数テーブルへの書き込みは、
> 必ずトランザクションで囲んでください。**
> 途中で失敗したとき、タグだけが残る中途半端な状態を防げます。

> ⚠️ **`rollBack()` の大文字小文字に注意。** `rollback()` ではありません（PDOのメソッド名）。

## ✍️ 手を動かす⑦ ─ エラーを種類ごとに扱う

**「ユーザーに見せるエラー」と「バグ」を区別します。**

```php
<?php
try {
    $stmt = $pdo->prepare(
        "INSERT INTO users (name, email, password_hash) VALUES (:name, :email, :hash)"
    );
    $stmt->execute([
        "name"  => $name,
        "email" => $email,
        "hash"  => password_hash($password, PASSWORD_DEFAULT),
    ]);

} catch (PDOException $e) {
    // エラーコードで分岐する
    $code = $e->errorInfo[1] ?? 0;     // MySQL のエラー番号

    if ($code === 1062) {
        // Duplicate entry（UNIQUE制約違反）
        $errors["email"] = "このメールアドレスは既に登録されています";
    } elseif ($code === 1452) {
        // 外部キー制約違反
        error_log("外部キー違反: " . $e->getMessage());
        $errors["general"] = "データの登録に失敗しました";
    } else {
        // 想定外 → ログに詳細、画面には一般的なメッセージ
        error_log("DB エラー: " . $e->getMessage());
        $errors["general"] = "システムエラーが発生しました。時間をおいてお試しください。";
    }
}
```

### 主な MySQL エラーコード

| コード | 意味 | ユーザーに見せる？ |
| --- | --- | --- |
| **1062** | Duplicate entry（UNIQUE違反） | ✅ 「既に登録されています」 |
| **1452** | 外部キー制約違反（親がない） | ❌ バグの可能性 |
| 1451 | 外部キー制約違反（子がある） | ✅ 「関連データがあるため削除できません」 |
| 1406 | Data too long（文字数超過） | ❌ 検証漏れ = バグ |
| 1048 | Column cannot be null | ❌ 検証漏れ = バグ |
| 1146 | Table doesn't exist | ❌ 設定ミス |
| 1045 | Access denied | ❌ 設定ミス |

> 💡 **UNIQUE制約違反（1062）だけは、ユーザーに見せる価値があります。**
> 「メールアドレスの重複」は、ユーザーが自分で直せるエラーだからです。
>
> **他は、PHPの検証で防ぐべきもの**です。到達したら、検証に漏れがあります。

### なぜ「PHPで重複チェック」だけでは不十分か

```php
// ❌ 同時アクセスで通り抜ける
$stmt = $pdo->prepare("SELECT COUNT(*) FROM users WHERE email = ?");
$stmt->execute([$email]);
if ($stmt->fetchColumn() > 0) {
    $errors["email"] = "既に登録されています";
} else {
    // ★ ここで別のリクエストが同じメールで INSERT すると、両方通る
    $pdo->prepare("INSERT INTO users ...")->execute([...]);
}
```

```
時刻  リクエストA            リクエストB
 1    SELECT → 0件
 2                           SELECT → 0件
 3    INSERT → 成功
 4                           INSERT → ★ 重複！
```

> 💡 **これが「UNIQUE制約が最後の砦」という意味です。**
> **PHPでチェックして親切なメッセージを出し、DBの制約で確実に防ぐ**——
> 両方やるのが正解です。

## ✍️ 手を動かす⑧ ─ リポジトリを書き換える

**第3部の `PostRepository` の中身だけを、DB版に差し替えます。**

`app/Repositories/PostRepository.php`（📋 完成形は `code/04-07/`）

```php
<?php
declare(strict_types=1);

namespace App\Repositories;

use App\Models\Post;
use PDO;

final class PostRepository
{
    public function __construct(private readonly PDO $pdo) {}

    /**
     * ページ単位で取得する
     *
     * @return array{posts: Post[], total: int, page: int, totalPages: int}
     */
    public function paginate(int $page, int $perPage = 10, string $keyword = ""): array
    {
        $where  = "";
        $params = [];

        if ($keyword !== "") {
            $where = "WHERE p.name LIKE :kw OR p.body LIKE :kw";
            // ★ LIKE のワイルドカードをエスケープする（4-8で詳しく）
            $params["kw"] = "%" . addcslashes($keyword, "\\_%") . "%";
        }

        // ① まず件数を数える
        $countSql = "SELECT COUNT(*) FROM posts p {$where}";
        $stmt = $this->pdo->prepare($countSql);
        $stmt->execute($params);
        $total = (int) $stmt->fetchColumn();

        $totalPages = max(1, (int) ceil($total / $perPage));
        $page       = max(1, min($page, $totalPages));
        $offset     = ($page - 1) * $perPage;

        // ② 該当ページだけを取得する
        //    ★ 相関サブクエリで返信数を取る（JOINの掛け算を避ける）
        $sql = "
            SELECT
                p.id, p.user_id, p.name, p.body, p.edit_token,
                p.created_at,
                u.name AS user_name,
                (SELECT COUNT(*) FROM comments c WHERE c.post_id = p.id) AS comment_count
            FROM posts p
            LEFT JOIN users u ON u.id = p.user_id
            {$where}
            ORDER BY p.created_at DESC, p.id DESC
            LIMIT :limit OFFSET :offset
        ";

        $stmt = $this->pdo->prepare($sql);
        foreach ($params as $k => $v) {
            $stmt->bindValue($k, $v);
        }
        $stmt->bindValue("limit",  $perPage, PDO::PARAM_INT);
        $stmt->bindValue("offset", $offset,  PDO::PARAM_INT);
        $stmt->execute();

        $posts = array_map(
            static fn(array $row) => Post::fromArray($row),
            $stmt->fetchAll()
        );

        return compact("posts", "total", "page", "totalPages");
    }

    public function find(int $id): ?Post
    {
        $stmt = $this->pdo->prepare("SELECT * FROM posts WHERE id = :id");
        $stmt->execute(["id" => $id]);

        $row = $stmt->fetch();
        return $row === false ? null : Post::fromArray($row);
    }

    public function save(Post $post): int
    {
        $stmt = $this->pdo->prepare(
            "INSERT INTO posts (user_id, name, body, edit_token)
             VALUES (:user_id, :name, :body, :edit_token)"
        );
        $stmt->execute([
            "user_id"    => $post->userId,
            "name"       => $post->name,
            "body"       => $post->body,
            "edit_token" => $post->editToken,
        ]);

        return (int) $this->pdo->lastInsertId();
    }

    public function delete(int $id): bool
    {
        $stmt = $this->pdo->prepare("DELETE FROM posts WHERE id = :id");
        $stmt->execute(["id" => $id]);
        return $stmt->rowCount() > 0;
    }

    public function count(): int
    {
        return (int) $this->pdo->query("SELECT COUNT(*) FROM posts")->fetchColumn();
    }
}
```

### 何が変わり、何が変わらなかったか

| | 第3部（JSON） | 第4部（DB） |
| --- | --- | --- |
| メソッド名 | `paginate` `find` `save` `delete` | **同じ** |
| 戻り値の型 | `Post` / `Post[]` | **同じ** |
| **呼び出し側のコード** | — | **ほぼ変わらない** |
| 中身 | `file_get_contents` + `json_decode` | `prepare` + `execute` |
| 1件検索 | **全件を読む（O(n)）** | **インデックスで1行（O(log n)）** |
| ページング | 全件読んで `array_slice` | **`LIMIT` で必要な分だけ** |
| 排他制御 | `flock` で全体をロック | **行単位のロック** |

> 💡 **これが 3-10 で「リポジトリパターン」を導入した理由です。**
> 保存先を変えるのに、`index.php` はほとんど変わりません。
>
> **「変更の影響範囲を1つのクラスに閉じ込める」**——これが設計の力です。

### ⚠️ 件数取得と本体取得で2回クエリを投げている

```php
$total = ...   // ① COUNT(*)
$posts = ...   // ② LIMIT 付きの本体
```

**これは正しい実装です。** ページ送りには総件数が必要で、
`LIMIT` を付けたクエリからは総件数がわかりません。

> 💡 MySQL には `SQL_CALC_FOUND_ROWS` という機能がありましたが、
> **MySQL 8.0.17 で非推奨になりました**。2回クエリを投げるのが現在の推奨です。

## ⚠️ つまずきポイントまとめ

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `Call to a member function on bool` | `ERRMODE_EXCEPTION` を設定していない | 必ず設定する |
| `SQLSTATE[HY000] [1045] Access denied` | ユーザー名・パスワードが違う | XAMPP は root/空、MAMP は root/root |
| `SQLSTATE[HY000] [2002] No such file or directory` | ソケットのパス（Mac） | `host=127.0.0.1` にし、`port=8889` を指定 |
| `SQLSTATE[HY000] [1049] Unknown database` | データベース名の間違い | `SHOW DATABASES;` で確認 |
| 日本語が `???` になる | DSN に `charset=utf8mb4` がない | DSN に追加 |
| `LIMIT ?` で構文エラー | エミュレーションモード | `EMULATE_PREPARES => false` |
| `fetch()` の結果が `false` | 該当行がない | `=== false` で判定 |
| `Invalid parameter number` | プレースホルダの数が合わない | 名前と数を確認 |
| 数値が文字列で返る | `STRINGIFY_FETCHES` | `false` に設定 |
| `rowCount()` が 0 | 値が変わっていない | 存在確認は `SELECT` で行う |
| `.env` が読めない | パスが違う / 公開ディレクトリ配下にある | `__DIR__` で指定し、`public/` の外に置く |

### `Invalid parameter number` の原因

```php
// ❌ プレースホルダが2つ、値が1つ
$stmt = $pdo->prepare("SELECT * FROM posts WHERE name = :name AND body = :body");
$stmt->execute(["name" => "太郎"]);

// ❌ 名前が一致していない
$stmt = $pdo->prepare("SELECT * FROM posts WHERE name = :name");
$stmt->execute(["user_name" => "太郎"]);

// ❌ ? と名前付きを混在させた
$stmt = $pdo->prepare("SELECT * FROM posts WHERE name = ? AND id = :id");
```

<?php
// クエリ回数を数えるための簡単なラッパー
final class CountingPdo
{
    public int $count = 0;

    public function __construct(private readonly PDO $pdo) {}

    public function prepare(string $sql): PDOStatement
    {
        $this->count++;
        return $this->pdo->prepare($sql);
    }

    public function query(string $sql): PDOStatement
    {
        $this->count++;
        return $this->pdo->query($sql);
    }
}

### 実測結果（参考）

[`code/04-07/n-plus-one.php`](../code/04-07/n-plus-one.php) を実行した結果です（📋 コピペ可）。

```
投稿 200 件 / ユーザー 20 人 のデータで計測

--- 10 件を表示する場合 ---
方法      クエリ回数    実行時間    取得行数
------------------------------------------------
N+1版     11 回         0.07 ms     10
JOIN版    1 回          0.02 ms     10
IN版      2 回          0.08 ms     10

--- 200 件を表示する場合 ---
方法      クエリ回数    実行時間    取得行数
------------------------------------------------
N+1版     201 回        0.96 ms     200
JOIN版    1 回          0.11 ms     200
IN版      2 回          0.12 ms     200
```

> ⚠️ **「1ms 未満なら問題ないのでは？」と思ったら、それが罠です。**
>
> この計測は、**同じプロセス内のメモリ上のデータベース**に対するものです。
> 実際のWebアプリでは、データベースは**別のサーバー**にあります。
>
> | | この計測 | 実際のWebアプリ |
> | --- | --- | --- |
> | 1回のクエリのコスト | 約 0.005ms | **1〜5ms**（通信の往復が含まれる） |
> | 201回なら | 約 1ms | **200〜1000ms** |
>
> **N+1問題は「本番環境で初めて顕在化する」**ため、非常に厄介です。
> ローカルでは快適だったページが、本番では5秒かかる——という事態が起きます。

> 💡 **「11回 vs 1回」を数字で見ると、忘れなくなります。**
